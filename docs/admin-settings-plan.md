# 관리자 설정 통합 기획안 (2026-10-21)

대표 요청: 관리자 메뉴의 설정이 화면마다 다른 모습으로 켜고 끄게 되어 있어 복잡하다.
같은 모양으로 · 메뉴(업무)별로 · 중복 없이 · 켜기/끄기 · 예약 켜기/끄기 · 예약 시각.

## 1. 지금 상태 (전수 조사 요약)

- 설정 화면 8곳: 관리자 메뉴 6(AI·Teams·아사나·Tally·온라인 발주·일반) + 메뉴 밖 2(파도소리 /factory/settings, 종합 리포트 수신자). 그 밖에 메타 판정 기준·입금 자동무시·VOC 분류·원가 예약이 각 화면 안에 있다.
- 켜기/끄기 모양 4가지(체크박스·칩·상태 배지 버튼·[켜기]/[끄기] 버튼), 저장 방식 4가지(즉시·카드별 [저장]·페이지 머리 [저장]·맨 아래 [저장]), 결과 표시 4가지(배너·글자·토스트·"저장했습니다 HH:MM").
- 예약 실행 체계 4가지: Vercel 크론(2개, 한도 참), Supabase pg_cron(5분 틱 등), 중계 서버 crontab, 외부 웹훅. 켜기 플래그 위치도 DB·코드 상수·crontab 으로 제각각.
- 중복
  1. Teams 웹훅 URL·켜기: B2B 4채널(Teams 연동) ↔ 파도소리 입출고(/factory/settings, 메뉴에 없음)
  2. 아사나: 토큰·VOC 프로젝트(아사나 연동) ↔ 파도소리 프로젝트·이벤트(/factory/settings)
  3. 알림 켜기 3겹: Teams 전체 → 알림 이벤트(B2B 10종) → 변경알림(상품마스터·생산·재고 14종). 같은 화면 안에서 저장 버튼·API가 다르고, 입금 확인필요·생산 상태 변경 알림은 끌 수 없음
  4. AI: 켜기 값 형식 3가지("1"·"off"·JSON), 프롬프트가 AI 설정·공지 화면·코드에 흩어짐
  5. 메일 수신자 3곳(종합 리포트 저장값·매출 리포트 1회 입력·비서 정기 리포트)
  6. 아침 일정 알림은 '자동 발송 사용'과 'Teams로 발송 켜기'가 둘 다 켜져야 나감
- 문제(같이 고침): '마지막 자동 발송'이 갱신되지 않음 · 'CRON_SECRET 미설정' 경고가 실제 발송 경로와 무관 · Teams URL을 화면에서 지울 수 없음 · 설정 저장 API 대부분이 관리자 검사 없음(로그인만 하면 저장)

## 2. 바뀐 모습

### 2-1. 화면 하나: 관리자 › 설정

왼쪽 = 업무 메뉴 목록, 오른쪽 = 그 메뉴의 설정 카드. 사이드바 '설정' 아래 6개 메뉴는 이 화면 하나로 합친다.

| 왼쪽 메뉴 | 들어가는 것 |
|---|---|
| 발주(B2B) | 발주 알림 10종, 아침 일정 알림(예약), 거래명세표 공급자·직인 |
| 생산·재고 | 생산·재고 알림 9종, 주간 생산 요청서 초안(예약)·AI 검토 포인트, 상품마스터 변경알림 5종, 원가 변경 예약 반영(예약, 표시) |
| 온라인 발주 | 중복 방지, 배송일지 박스·단가 |
| 매출·리포트 | 종합 리포트·매출 리포트 메일 수신자(한 곳), 정기배송 수집(예약) |
| 고객(VOC·CS) | 클레임·고객문의 수집(예약), 입금 확인필요 알림, Tally |
| AI | 비서 켜기·월 상한, 공통·기능별 모델, 프롬프트(회의록·CS·공지) |
| 파도소리 | 입출고 알림(Teams), 아사나 업무 등록 |
| 연결(채널·키) | Teams 채널 주소 5개(B2B·변경알림·클레임·고객문의·파도소리), 아사나 토큰, Tally 키 — 주소·키는 여기 한 곳에만 |

계정 관리는 지금처럼 따로 둔다. 광고 켜기/끄기·인스타 규칙·VOC 분류는 '설정'이 아니라 업무 동작이라 각 화면에 둔다.

### 2-2. 한 가지 모양: 설정 줄(SettingRow)

모든 항목이 같은 줄 하나로 보인다.

```
[이름]                         [켜짐 ●]  [ 켜기/끄기 스위치 ]
 한 줄 설명                                   [자세히 ›]
 ─ 예약 있는 항목만 ─
 예약  [ 예약 켜기/끄기 ]  매일 06:00 · 16:00  (월~금)   마지막 실행 10-21 06:00 성공
```

- 켜기/끄기·예약 켜기/끄기 = 누르면 바로 저장 + 5초 '되돌리기'(디자인 기준 '저위험 상태 변경')
- 시각·요일·수신자·주소 같은 값 = [자세히 ›] 오른쪽 창에서 고치고 [저장] 한 번
- 상단 배지: 켜짐(초록) · 꺼짐(회색) · 예약 꺼짐(노랑) · 연결 안 됨(빨강, 주소·키 없음)
- 알림이 위에서 막혀 있으면 줄에 이유를 쓴다(예: "Teams 전체가 꺼져 있어 나가지 않음")

### 2-3. 예약 하나로: 예약 틱

앱이 시각을 정하는 예약은 이미 있는 pg_cron 5분 틱 하나에 모은다. 작업마다 `{켜짐, 시각들, 요일}` 을 DB 에 두고 틱이 '지금 할 일'만 실행·기록(마지막 실행·성공/실패)한다.

| 작업 | 지금 | 바뀐 뒤 |
|---|---|---|
| 아침 일정 알림 | 5분 틱 + Vercel 크론 2개 | 5분 틱(그대로) — Vercel 크론은 예비로 유지 |
| 주간 생산 요청서 초안 | 중계 서버 수 13:50 고정 | 5분 틱으로 이동 → 화면에서 요일·시각·켜기 |
| 비서 정기 리포트 | 코드 상수로 숨김 | 그대로 숨김(대표 결정 유지) |
| 원가 변경 예약 반영 | pg_cron 00:10 | 그대로, 화면엔 표시만 |
| 클레임·문의 수집(10분)·정기배송 수집(23:59)·채널 재고 명령(2분)·카탈로그 | 중계 서버 | 중계 서버에서 계속 돈다(외부 API 접근 때문). 앱 쪽에 켜기/끄기 스위치를 두어 꺼져 있으면 받은 요청을 바로 끝낸다. 시각은 표시만 |

## 3. 정할 것

1. 화면 구조 — **권장: 화면 하나(왼쪽 업무 메뉴)** / 지금처럼 메뉴 6개를 두고 모양만 통일
2. 켜기/끄기 저장 — **권장: 바로 저장 + 되돌리기** / 모든 변경을 [저장] 버튼으로
3. 예약 범위 — **권장: 앱 예약(아침 알림·주간 초안)은 시각까지 화면에서, 중계 서버 작업은 켜기/끄기만** / 중계 서버 작업도 시각까지(서버 crontab 을 5분 틱으로 바꾸는 작업 추가)
4. 파도소리 설정 — **권장: 관리자 설정으로 합치고 /factory/settings 는 없앰**(파도소리 화면엔 씨몬스터 흔적이 없어야 해서, 설정은 씨몬스터 관리자 쪽이 맞다) / 따로 둠
5. 알림 끄기 범위 — **권장: 지금 끌 수 없는 알림(입금 확인필요·생산 상태 변경)도 스위치를 붙인다** / 그대로

## 4. 순서

- 1차(화면): 공용 SettingRow·오른쪽 창, 통합 화면, 기존 저장 키 그대로 읽고 씀(마이그레이션 없음), 옛 화면 주소는 새 화면으로 이동, 설정 API 관리자 검사, Teams 주소 지우기·마지막 발송 표시 수정
- 2차(예약): 예약 설정 표(마이그레이션 1개) + 틱이 주간 초안까지 실행, 중계 서버 작업 켜기/끄기 게이트, 마지막 실행 기록
- 3차(정리): 안 쓰는 키(analyst_auto·flow_bot_*·zapier 유산·digest_last_sent) 삭제, 가이드 갱신
