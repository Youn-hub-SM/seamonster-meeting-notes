# 종합 리포트(/briefing) 가시성 개선 기획안

2026-10-13 · 대표 요청 "이 종합리포트를 가시성 좋게 바꿔보고 싶어" · 상태: **1차·2차 구현 완료(2026-10-13, §7 전부 추천안 채택, 운영 배포)** — 3차(§8 13~17)는 2주 운영 뒤 선택

## 1. 목표

대표가 /briefing 을 열어 **30초 안에 '얼마였나 → 평소 대비 어땠나 → 왜 → 무엇을 확인하나'** 를 읽게 한다.

방법은 **코드 렌더뿐** — DB 행에 이미 저장된 facts(JSON)와 report_md(마크다운) 파싱으로 KPI 타일·섹션 카드·배지·접기를 그린다.
프롬프트 변경·추가 AI 호출 0. 옛 리포트(헤딩 번호 다름·고객의 소리 없음·facts 일부 없음)는 지금과 같은 모양으로 폴백. 팀즈 카드는 별개 렌더로 26KB 한도 안에서 손본다.

## 2. 지금 화면의 문제

- 마크다운을 평탄하게 렌더한다 — 모든 줄이 같은 무게, 숫자 강조 없음, 증감 색 없음, 섹션 이동 없음.
- 길이의 대부분은 AI 글(일일 45줄 이내)이 아니라 코드가 끼운 표다 — 광고 추이 2개 × 14행, 캠페인 전체 2개 × N행. 핵심이 표 사이에 묻힌다.
- '한 줄 요약'과 '확인할 것'(대표가 실제로 읽는 두 곳)이 본문과 구분되지 않는다.
- 표 글자 14px(본문 15px 규칙 위반), 인라인 px·hex 가 섞여 있다.

## 3. 원칙

1. **숫자는 코드(facts), 글은 AI.** 가시성은 렌더로만. 프롬프트 변경은 3차 선택 항목 하나뿐(캐시 1회 재작성 ≈ $0.05 미만).
2. **섹션 순서·헤딩 글자 불변** — 한 줄 요약 → 1. 매출 → 2. 광고 → 3. 재고 → (주간) 4. 고객의 소리 → 눈에 띄는 변화와 원인 → 확인할 것. SEC 정규식·팀즈 축약·프롬프트가 전부 헤딩 글자에 묶여 있다. 렌더러는 꾸미기만 하고 재배열하지 않는다.
3. **색은 신호가 있는 네 곳만** — KPI 매출 증감(|값|<3% 중립), 매출 표의 증감·대비 열, 재고 상태(품절·부족) 배지, 확인됨/추정 배지. **광고는 어디에도 판정 색 없음**(2026-09-30 대표 원칙). 표 안 금액은 중립(design-system §4).
4. **공용 컴포넌트·토큰만** — `.b2b-dash-grid > .b2b-stat-card`(KPI) · `.b2b-card + .b2b-card-head > .b2b-card-title`(섹션) · `.b2b-status-pill`(배지, 색은 lib 색 지도) · `.b2b-table-wrap > .b2b-table`(.num·.is-responsive·tr.is-overdue/.is-urgent) · `.sm-tabs > .sm-tab`(이동 바) · charts.tsx `TrendChart`/`ComboBarLine` · format.ts `won()`. 페이지 전용 클래스는 `.brf-*` 접두사로 `app/b2b/b2b.css` 끝에 한 블록(값은 전부 `var(--sm-*)`).
5. **폴백 = 지금 모양** — facts 칸이 없으면 그 타일을 숨긴다(0 으로 그리지 않음), 타일이 하나도 없으면 띠를 숨긴다, 헤딩이 없으면 평탄 렌더, 표 파싱 규칙에 안 맞으면 색 없이 글자 그대로.
6. 공용 파일(`app/b2b/b2b.css`·`app/lib/briefing.ts`)은 끝에 블록 추가·선택 인자 추가만, 고치기 전 다른 세션에 알린다. 화면 변경 커밋은 guide-data.ts 를 같은 커밋에서 갱신.

## 4. 화면 구성(위에서 아래로)

### 4-1. 메타 줄(12px, 기존 자리)
기간·매출 반영·생성 시각·모델·비용은 그대로. 2차에서 발송 부분만 `.b2b-status-pill` — '발송 전'(warning) / '팀즈 발송 10-13 14:31'(success) / '이전 버전 발송'(warning).

### 4-2. KPI 타일 띠 — 4개 고정(일일·주간·월간)
`.b2b-dash-grid.brf-kpi > .b2b-stat-card` × 4. 값은 `won()`+'원', 증감은 값 아래 `.b2b-status-pill`(≥+3 success · ≤−3 danger · 그 사이 중립 `--sm-bg-subtle/--sm-text-mid`). 힌트는 집계 기준 한 줄만(카피 규칙).

| 타일 | 값 | 증감 pill(주 비교) | 힌트 |
|---|---|---|---|
| ① 소매 매출 | `sales.retail_total.rev` | 일일 `vs_base_pct` '4주 같은 요일 평균 대비' / 주간 `vs_prev_pct` '전주 대비' / 월간 `per_day_vs_prev_pct` '전월 대비(하루 평균)' | 일일 '전일 {prev_day_rev}원 · 주문 {orders}건' / 주간 '4주 평균 대비 {vs_base_pct}% · 하루 평균 {per_day_rev}원' / 월간 '작년 같은 달 대비 {vs_last_year_pct}% · 하루 평균 {per_day_rev}원' |
| ② 광고비(VAT 제외) | `ads.spend_ex_vat_total` | 없음(색 없음) | 'ROAS 메타 {meta.roas} · 네이버 {naver.roas}'(purchases null 이면 '미확정') |
| ③ 재고 | '품절 {now.soldout} · 부족 {now.short}' — soldout>0 값 danger, short 만 >0 warning | 없음 | '{urgent_top[0].name} {days}일 · 오는 중 {inbound_total}(마감 지남 {inbound_overdue})' |
| ④ 기간 고유(결정 1) | 일일 '월 누적' `mtd.rev` / 주간 '고객의 소리' '문의 {voice.naver.total} · VOC {voice.voc.total}' / 월간 '월말 재고 금액' `inventory.value.end` | 일일 `mtd.vs_prev_pct` / 주간 없음 / 월간 전월말 대비(중립색) | 일일 '도매 포함' / 주간 '미답변 {unanswered}'(>0 warning pill) + '늘어난 유형 {voc.rising[0].category}' / 월간 '매입 {purchase.amount}원({basis})' |

출처: 새 `app/lib/report-kpi.ts` `reportKpi(period, parts)` 가 기간별 칸 이름 차이를 한 곳에서 흡수해 `{ sales, ads, inventory, extra, charts }` 로, GET /api/analyst 가 `report.kpi` 로 전달(select 에 JSON 경로 별칭 — 캠페인 배열·tool_log 는 DB 에서 꺼내지 않는다).
CSS: 데스크톱(min-width 769px)에서만 `.brf-kpi { grid-template-columns: repeat(4,1fr) }` + 값 `var(--sm-fs-2xl)`(23px) — 기본 auto-fit minmax(250px) 는 960 폭에서 3+1 로 깨진다. 모바일은 기존 768px 규칙(2열·20px) 그대로.
폴백: kpi null → 띠 생략. `sales.ready=false` → ① '매출 없음'(text-light). 주간·월간 `complete=false` → 힌트 앞 '잠정 ·'. 매체 ok=false → '조회 실패'. `inventory.now` null(끝난 지 7일 넘은 기간 재생성) → ③ 생략. ④ 칸 없으면 생략.

### 4-3. 한 줄 요약 카드
'## 한 줄 요약' 본문을 테두리 카드(`.b2b-stat-card`)에: 라벨 '한 줄 요약'(12px) + 문장 `var(--sm-fs-lg)`(17px) 600. 숫자·% 에 색 없음(타일이 신호). 오른쪽 끝(모바일은 아래)에 **'확인할 것 N건'** info pill — 누르면 확인할 것 섹션으로 scrollIntoView.
출처: report-sections.ts 에 `SEC.summary`·`SEC.sales` + `splitSections(md): {kind, heading, lines}[]`(순수 함수).

### 4-4. 섹션 공통 틀(## 마다)
`<section id="brf-{kind}">` `.b2b-card > .b2b-card-head > span.b2b-card-title`(헤딩 글자 그대로, 17px/700, 아래 1px 선). 섹션 사이 `var(--sm-space-6)`(32px). ### 은 `var(--sm-fs-base)` 700 + `var(--sm-space-3)` 로 ## 와 위계를 벌린다. 본문 15px/1.8 유지. 줄 렌더러(표·글머리·굵게)는 그대로 두고 **바깥만 감싼다**(옛 마크다운 회귀 방지). `.brf-md .b2b-table tbody tr { cursor: default; background: transparent }`(클릭되는 표가 아니다).

### 4-5. 1. 매출
- AI 채널 표: 14px 제거(15px). 머리글에 '증감' 또는 '대비' 가 든 열의 셀이 `/^[+\-−]\d{1,3}(\.\d+)?%$/` 전체 일치일 때만 글자색(+ success · − danger · |값|<3 중립). '-'·'+8%p'·부호 없는 % 는 무색. 첫 칸 /합계/ 행 `.brf-total`(bg-subtle·700). 열 ≤6 → `.is-responsive` + `data-label` 모바일 카드(2차).
- 본문 줄(도매·신규/재구매·월 누적)은 글자 그대로 — 줄글 속 % 색 없음.
- 2차: 섹션 끝에 주간 요일별 7막대 / 월간 주차별 `TrendChart`(fmtAxis moneyCompact, accent `var(--sm-orange)`) — `facts.sales.trend` 에 이미 있음, AI 비용 0. 일일은 시계열이 없어 없음(3차 선택).

### 4-5a. 접기 원칙 — 글은 한 글자도 줄지 않는다(대표 우려 2026-10-13)
AI 본문(모든 섹션)은 전부 그대로. 접히는 것은 코드 표 두 종류(캠페인 전체 표의 상위 5 밖·광고 추이 구간별 표)뿐이고, 한 번 누르면 지금과 똑같은 전체 표가 나온다. 재고 주의 품목·고객의 소리 집계 표는 접지 않는다.
~~KPI 띠 오른쪽 [전부 펼치기] 토글~~ — 2026-10-13 배포 뒤 대표 피드백("전혀 무쓸모")으로 제거. 접힌 표는 각자 눌러 펼친다. 기본을 '전부 펼침'으로 두는 것은 결정 4 의 선택지로 남아 있다.

### 4-6. 2. 광고
- AI 매체별 줄 그대로, 색 없음.
- '### 광고 추이': 요약 줄 + `ComboBarLine` 그래프는 항상 보이고, 그 아래 구간별 표 2개만 `<details class="brf-fold">` 로 접는다(summary '구간별 표 N구간'). 그래프 없는 옛 리포트는 펼침.
- '### 캠페인 전체': **합계 행 + 지출 상위 5행** 기본, 나머지 `<details>` summary '캠페인 전체 N개'(결정 4). 가로 스크롤 유지, 15px(결정 5), 모바일 카드 변환 없음(11~12열).
- 표 종류·합계 행 정규식(`/캠페인$/`·`/추이$/`·`/품목$/`·`/^합계 \d+개/`)을 report-sections.ts 상수(TABLE_KIND·TOTAL_ROW)로 빼 analyst.ts adTablesForTeams 와 공유.

### 4-7. 3. 재고
- '### 재고 주의 품목' 표는 항상 펼침(행동용, ≤6행). '상태' 셀 → 배지: 품절 = danger + `tr.is-overdue`, 부족 = warning + `tr.is-urgent`(결정 3). 버티는 날 ≤3 셀 danger 글자. 색은 `app/lib/inventory.ts` 에 `INV_WATCH_COLOR` 추가(§4 색 지도 — 화면에서 색 선언 금지).
- 2차: `facts.inventory.now.watch` 가 있으면 코드가 표를 그려 상태·data-label 을 정확히, 없으면 마크다운 파싱.
- 표 아래 기준 줄(- 품절 = …)은 집계 기준이라 유지, sm-faint 12px.

### 4-8. 4. 고객의 소리(주간만)
- '(미답변)' 로 끝나는 줄은 끝 괄호를 warning pill 로, '(답변 N시간)' 은 중립 pill.
- '### 고객의 소리 집계' 표는 접지 않는다(≤8행, 미답변·손해가 행동 근거). '문의 중 미답변' 값>0 warning pill, 'VOC 손해 합계' 는 전주보다 크면 danger 글자(작으면 중립). 3열 → 모바일 카드.
- 표 아래 '늘어난 유형: 배송 3(전주 1)' 배지 줄은 `facts.voice.voc.rising` 있을 때만.

### 4-9. 눈에 띄는 변화와 원인
'- ' 줄마다: `/\(원인[:：]?\s*(확인됨|추정)/` 또는 `/\((확인됨|추정)[,)·\s]/` 가 있으면 줄 맨 앞에 pill — **확인됨 = success, 추정 = warning**(정확 패턴 우선, 없으면 단어 경계 토큰 폴백 — '추정된다' 같은 일반 용법 제외). `/^(.+?)\s*(→|->)\s*(.+)$/` 로 나뉘면 앞(변화) 600 굵기, 뒤(원인·근거) 다음 줄 들여쓰기(`.brf-cause`) — 스캔하면 변화만 먼저 읽힌다. 줄 안 숫자·% 색 없음.

### 4-10. 확인할 것(마지막) — 행동 상자
한 줄 요약과 짝이 되는 테두리 카드(`.b2b-stat-card`): 라벨 '확인할 것 · N건' + 번호 목록(1. 2. 3.). 체크박스는 1차에 넣지 않는다(결정 6). 리포트의 시작(요약)과 끝(행동)이 테두리 카드로 액자가 된다.

### 4-11. 섹션 이동 바(2차) — KPI 띠와 한 줄 요약 사이, 스크롤 시 상단 고정
`.sm-tabs > .sm-tab` '요약 · 매출 · 광고 · 재고 · (고객의 소리) · 변화 · 확인(N)'. 누르면 scrollIntoView, is-active = 지금 보는 섹션(IntersectionObserver). `position: sticky` — 데스크톱 top 0, 모바일 top 52px(상단바 `.app-topbar` z-index 40 아래, z-index 30). 모바일은 한 줄 가로 스크롤. SEC 매칭 섹션이 2개 이하면 숨김.

### 4-12. 리포트 아래 '광고 추이' 별도 카드·하단 '리포트 설정'(관리자) — 그대로.

## 5. 팀즈 카드(별개 렌더, briefing.ts briefingCardBody — 줄 = TextBlock, 표 행 = ColumnSet ≈0.4~0.9KB, 그래프 불가)

2차(항목 12, +≈600B):
1. 제목에 헤드라인 — '일일 종합 리포트 · 10/12 · 소매 3,210만(+8%)'. 알림 미리보기만으로 어제가 보인다(≈30B).
2. 제목 아래 핵심 TextBlock 3~4줄 — 매출(color Good/Attention, |값|<3 Default) · 광고비(Default) · 재고(soldout>0 Attention, short 만 Warning) · 주간 고객의 소리(미답변>0 Warning) ≈500B. ColumnSet 2×2 는 휴대폰에서 열이 세로로 쪼개져 쓰지 않는다.
3. ## TextBlock 에 separator(+≈100B), 확인할 것은 '1. 2. 3.' 번호 목록.
4. lead 를 `teamsCardBytes`·`postTeamsMarkdown` 의 같은 payload 로 재 한도 계산(26,000 측정 · 27,500 거부)이 어긋나지 않게.

3차(항목 13·14, 결정 8): ≤5열 표(매출 채널·고객의 소리 집계·재고 주의)를 FactSet(행당 ≈60~80B)로, 캠페인 표는 항상 상위 10 + 합계, 캠페인 줄은 지출·구매·ROAS·전기 ROAS 4지표만. '화면에서 보기' OpenUrl 은 공개 URL env 가 생기면.

하지 말 것: 줄 단위 색 스니핑('품절' 포함 줄 Attention — '품절 0' 오탐), 그래프 이미지 첨부(웹훅 불가), ShowCard 접기(워크플로 웹훅 불안정), ColumnSet 열 늘리기.

## 6. 모바일(768px 이하가 기준 화면)

KPI 4개 = 2행(기존 규칙), 증감 pill 은 값 아래 별도 줄. 요약·확인할 것 카드는 모바일 패딩 16px, 'N건' pill 은 문장 아래. 열 ≤6 작은 표는 `data-label` 카드 변환(2차), 11~12열 캠페인·7열 추이 표는 가로 스크롤 + 기본 접힘(카드로 바꾸면 행마다 12줄 = 수십 화면). 그래프는 프리미티브 minWidth 480 + overflow(기존). 이동 바는 top 52px 고정, 한 줄 가로 스크롤. 핵심만 보면 휴대폰 기준 약 4~5화면.

## 9. 반려한 생각(이유)

- 본문 줄글의 서명 % 에 색 — 오탐이 구조적('광고비 +20%'·도매 '-30%' 참고 수치). 색은 타일과 매출 표 증감 열로 한정.
- 전역 '핵심만/전체' 모드 + localStorage — 블록별 접기와 효과가 같은데 개념을 하나 더 얹는다. 상위 5 + 합계가 클릭 없이 더 많이 보여 준다.
- 팀즈 KPI 를 ColumnSet 2×2 / 마크다운 한 줄로 — 휴대폰에서 쪼개지거나 색을 못 입힌다. 줄마다 TextBlock.
- 메타·네이버 ROAS 두 타일 — 4칸 중 2칸이 광고면 '광고는 판정 없이' 와 반대.
- 6~8 타일 — 모바일 3~4행이 돼 띠가 본문을 밀어낸다.
- 단어 기반 색('늘었다·줄었다') — '광고비가 줄었다'·'품절이 늘었다' 처럼 방향과 좋고 나쁨이 뒤집힌다.
- 핵심 패널용 요약 재생성 같은 추가 AI 호출 — facts 에 다 있다.
- 새 `app/briefing/briefing.css` 파일 — 클래스 정의는 globals.css·b2b.css 두 파일뿐(design-system). `.brf-*` 블록을 b2b.css 끝에.
- 타일 안 스파크라인을 page.tsx 에서 SVG 로 — 자체 차트 금지. 필요하면 charts.tsx 에 프리미티브로, 3차 이후.
- 섹션 재배열·'핵심만' 에서 변화·확인할 것을 위로 — '데이터 먼저, 해석 뒤' 는 2026-10-01 대표 결정. KPI 띠·요약 카드가 결론을 맨 위에 준다.
- 일일 매출 타일의 주 비교를 전일로 — 이상 판정·헤드라인 기준이 '4주 같은 요일 평균' 이라 글과 숫자가 같은 말을 해야 한다.
- 저장 없는 체크박스 모양·☐✓ 기호·이모지(팀즈 포함).

## 10. 위험

- 기간별 facts 칸 이름이 다르다 — report-kpi.ts 한 곳에서 흡수, 세 기간 + 옛 + 매출 없음 + 재고 실패 + now=null 을 화면으로 확인. 분기 누락은 '·' 로 조용히 비어 보인다.
- `.b2b-dash-grid` auto-fit minmax(250px) — 960 폭에서 4개가 3+1. `.brf-kpi` 4열은 min-width 769px 미디어 안에만.
- 표 파싱 규칙이 renderAdTables·renderInventoryTable·프롬프트 표 형식에 묶여 있다 — 정규식 상수 공유, 실패하면 지금 모양 폴백.
- b2b.css·briefing.ts 는 공용 파일 — 다른 세션 공지, 끝에 추가만. `.brf-*` 중복 grep.
- 팀즈 한도 — lead 를 같은 payload 로 재지 않으면 26KB 를 넘겨 웹훅이 202 를 주고 게시만 조용히 실패(그날 리포트 전체가 안 감). 캠페인 30개·주간 voice 케이스 측정.
- AI 가 '확인됨·추정' 을 변형하면 배지만 빠진다(글은 보임) — 2~3주 보고 항목 16.
- 테스트가 없다 — tsc·build 는 파싱·색 오용을 못 잡는다. 저장된 report_md 로 스크립트 확인 + 대표 스크린샷(데스크톱·휴대폰).
- sticky 바 — 상단바는 52px 하나뿐, 60/64px·100vh 금지.
- 옛 리포트 일괄 재생성은 비용 때문에 하지 않는다 — 폴백이 '지금과 같은 평탄 렌더' 여야 한다.
- 이 기획은 마이그레이션·facts 저장 변경이 없다(항목 15 만 facts 에 칸 추가, 스키마 변경 없음). DB 가 하나(베타 = 운영)라도 안전.
