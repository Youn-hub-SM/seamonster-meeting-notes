# CRM 메시지맵 개편 기획 — 판매 채널별 목록 + 화면 새로 (2026-11-06)

상태: 대표 결정 대기
배경: 엑셀 가져오기로 실제 발송 메시지 63건(공식몰 55·네이버 8, 발송 수단 4종)이 들어온다. 지금 /crm 은 2026-07 시드 30개 때 만든 구조(여정 스테이지 리본 + 표 인라인 편집 + 통계)라 ① 판매 채널(공식몰·네이버)이 1차 축이 아니고 ② 화면이 어포던스·디자인 결정(10-14·10-17) 이전 모양이다. 대표 지시(11-06): "판매 채널별 메시지 목록을 두는 게 좋겠다", "UI 가 옛날 버전 같으니 개선".

## 1. 목표
- 첫 화면에서 **공식몰 / 네이버** 를 고르면 그 채널에 나가는 메시지가 단계 순서대로 한 표에 보인다.
- 메시지 하나를 누르면 본문·버튼 링크·트리거·UTM·성과가 한 패널에 보이고 거기서 고친다.
- 한 고객이 며칠에 몇 통을 받는지(피로도)를 채널별로 본다.
- 화면은 디자인 시스템(KPI 타일·경계 카드·회색 배지·sticky 표·드로어)으로 다른 화면과 같은 모양.

## 3. 원칙
- 판매 채널 = 고객군(customer: mall·naver·etc). 발송 수단(데이터라이즈·블룸ai·솔라피·카페24)은 배지로만. 솔라피 = 네이버 고객만(규칙은 이미 코드에).
- 메시지 하나의 편집은 드로어 한 곳. 인라인 편집은 없앤다(같은 값을 두 곳에서 고치는 혼란 제거).
- 새 컴포넌트를 만들지 않는다: `.b2b-stat-card`, `.sm-tabs`, `.b2b-table.is-compact.is-sticky-head`, `.b2b-status-pill`(회색), `.b2b-modal`(드로어 변형 `.crm-drawer` 만 전용 CSS), `charts.tsx`.
- 안내 문구 없음. 빈 상태 3요소. 모션 없음.
- 데이터·API 는 그대로(crm_messages·crm_send_stats·GA). 마이그레이션 없음.

## 4. 설계
### 4-1. 화면 구조
```
[CRM 메시지맵]                              [+ 메시지 추가] [엑셀로 가져오기] [엑셀 내려받기] [선택지]
KPI: 메시지 63 · 활성 63 · 추적 38 · 이번 주 클릭률 2.4%
세그먼트: 전체 | 공식몰 55 | 네이버 8          보기: 목록 | 여정 | 성과          [검색]
──────────────────────────────────────────────────────────────
목록: ▸ 유입/인지 (2)  ▸ 첫 구매 (5) … 단계 머리 클릭으로 접기
   메시지명 | 발송 수단 | 유형 | 트리거 | 링크 | 상태 | 클릭률
```
### 4-2. 목록 표 열
메시지명(비고 태그 포함) · 발송 수단 배지 · 유형 · 트리거 D+n(조건 메모는 툴팁 아닌 두 번째 줄 12px) · 링크(버튼 수, UTM 있으면 캠페인명) · 상태 배지 · 클릭률(성과 있을 때만). 단계 묶음은 stage_num 순, 안은 sort_order.
### 4-3. 드로어
오른쪽 480px 패널(모바일은 전체). 위: 메시지명·채널·수단·상태 토글. 본문 미리보기(카카오 말풍선 모양 아님, 흰 카드에 pre-line). 버튼 링크 목록(버튼명 추정 = content 슬러그, 주소, [UTM 만들기에서 열기] 링크). 트리거·D+n·조건 메모·발송 시점. UTM 캠페인·매체·term. 솔라피 템플릿(네이버 솔라피만). 기간·태그. 아래 [변경 저장] [메시지 삭제].
### 4-4. 여정 타임라인
**(11-09 축 교체)** 행 = D+n(값 있는 것만, 시간 순), 열 = 트리거(선택지 순), 칸 = 그 날 나가는 메시지 칩. 대표: "세로축이 D-day, 가로축이 트리거". 같은 칸 2개 이상이면 칸 테두리 danger(피로 주의). 상시·행사는 아래 별도 띠. 채널 세그먼트 적용.
### 4-5. 성과
WeeklyStats 를 그대로 쓰되 채널 세그먼트를 넘겨 수단·캠페인을 거른다. 통계 탭의 캠페인 GA 표는 성과 아래로 합친다.

## 5. 비용·부하
API 호출은 지금과 같다(메시지 1회·옵션 1회·GA 1회·주간 성과 탭 열 때). 새 호출 없음. 번들은 page.tsx 951줄 → 목록·드로어·여정·성과 4파일로 나눠 비슷한 분량, 인라인 편집 코드가 빠져 줄어든다.

## 6. 대표 결정
1. 1차 축: (가) 맨 위 세그먼트 전체/공식몰/네이버, 모든 보기에 적용(권장) / (나) 지금처럼 필터만.
2. 목록 모양: (가) 단계별 묶음 표, 접기·sticky 머리(권장) / (나) 카드 그리드.
3. 편집: (가) 드로어 한 곳으로 통일, 표 인라인 편집 삭제(권장) / (나) 둘 다 유지.
4. 여정 보기: (가) 트리거 × D+n 타임라인으로 교체(권장) / (나) 스테이지 리본 유지 / (다) 여정 보기 삭제.
5. 옛 가져오기(시드 30개·CSV 붙여넣기)·기준일 필터: (가) 삭제(권장) / (나) 유지.
6. 성과: (가) 주간 성과 + 통계를 '성과' 하나로 합치고 채널 적용(권장) / (나) 그대로.

## 8. 위험
- 표 인라인 편집에 익숙한 직원 → 드로어에서 같은 칸을 한 번에 보여 주고, 저장은 [변경 저장] 하나.
- 여정 타임라인은 D+n 이 채워진 메시지만 보인다(상시·행사는 띠). 가져오기가 D+n 을 채우므로 63건 중 상시 23건은 띠에 간다.
- 솔라피 발송 수 연결(템플릿 ID)은 네이버 8건만 — 공식몰 수단은 주간 성과의 직접 입력·CSV 가 있어야 클릭률이 뜬다(2단계 CSV 는 보류 상태).

## 11-09 성과 보기 개편(대표 3건)

- 접기(`details`) 전부 폐지. 펼친 구역 카드 순서: 이 주 KPI 4(전주 대비 %·%p) → **메시지별 클릭률 최근 12주 표** → 이 주 메시지별 성과 → 주간 클릭률·주간 발송 차트(2열) → 수단별 발송·GA 매체별(2열) → 이 주의 기록.
- 12주 표 = `/api/crm/stats` 의 `history`(`trackedHistory`, app/lib/crm-stats.ts): 발송은 솔라피 템플릿 → 직접 입력 → **주별 추정**(`estimateAudienceWeekly`, 트리거 조합당 SQL 한 번, `date_trunc('week', d + n)`), 클릭은 GA 날짜×캠페인(kakao) 한 번을 주로 묶음. 전체 줄 = 수단별 기록 합 ÷ kakao 세션 합(KPI 와 동일). 끝 주 = 보고 있는 주라 '이전 주'를 누르면 표도 밀린다.
- 칸: 클릭률 %(목표 있으면 달성 초록·미달 붉게), 발송 수 없는 주는 클릭 수만 연하게, 둘 다 없으면 점. 이 주 열은 `--sm-orange-light`.
