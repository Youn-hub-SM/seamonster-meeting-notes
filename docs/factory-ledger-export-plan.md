# 파도소리 기록 종류 확장·엑셀 추출 기획안

- 작성일: 2026-11-20
- 대표 지시: pdsr.kr 에서 매입·생산·매출·재료 투입·이동을 구분해 적고, 그 기록을 ERP 엑셀 두 양식으로 내려받는다. [예상] 화면은 그대로 둔다.
- 상태: 기획안. 대표 결정(8장) 뒤에 만든다.

## 1. 무엇을 만드는가

1. pdsr.kr 의 입고·출고 기록에 **구분**을 붙인다. 지금은 입고·출고·조정 세 가지뿐이다.
2. 구분에 필요한 칸(보관처, 단가, 규격 등)을 기록 창에 더한다.
3. 히스토리 화면에 **[엑셀 추출]** 을 넣어, 기간을 정해 두 양식으로 내려받는다.
   - `원료출고제품매출현황` 양식(38열): 매출·재료·반품
   - `매입생산현황` 양식(30열): 매입·생산

내려받은 파일은 ERP 에서 받은 파일과 열 이름·순서가 같아서, [예상] 화면의 [데이터 올리기]에 그대로 넣을 수 있다.

## 2. 지금 기록과 ERP 양식의 차이

ERP 엑셀을 뜯어 본 결과다(3년, 16만 행).

| ERP 구분 | 3년 행 수 | 뜻 | pdsr.kr 에 지금 있는가 |
|---|---:|---|---|
| 매입 | 6,454 | 원물·상품을 사 옴 | 입고로 적을 수는 있으나 매입인지 생산인지 구분이 없다 |
| 생산 (보관처 있음) | 13,982 | 만들어 창고에 넣음 | 입고로 적는다. 구분 없음 |
| 생산 (보관처 없음) | 52,012 | 주문 받은 날 만들어 바로 나감 | **없다.** 창고를 거치지 않아 재고 기록에 안 잡힌다 |
| 재료 | 27,481 | 현장으로 투입(원물, 반제품) | 출고로 적는다. 구분 없음 |
| 매출 (보관처 있음) | 7,408 | 창고에서 거래처로 | 출고로 적는다. 구분 없음 |
| 매출 (보관처 없음) | 52,504 | 그날 만든 것을 거래처로 | **없다** |

| 이동 | 약 2,200 | 창고 사이 옮김. 적요에 `현이이고`로 적힘 | **없다.** 창고 구분 자체가 없다 |

칸으로 보면 이렇다.

| ERP 칸 | pdsr.kr 지금 | 필요한 일 |
|---|---|---|
| 일자 | 거래일 | 그대로 |
| 매출처·매입처 | 거래처 칸 하나 | 구분에 따라 매출처 또는 매입처로 내보낸다 |

| 규격 | 상품마스터에 품목마다 하나 | ERP 는 줄마다 다르다(2,900종). 5장 결정 필요 |

| 매입일자·입고일자(출고 파일) | 로트의 입고일 | 그 로트가 들어온 날을 내보낸다 |
| 단가·금액 | 없음(상품마스터에 원가·판매가만) | 칸 추가. 5장 결정 필요 |
| 본선명 | 없음 | 칸 추가(선택 칸) |
| 취급자 | 기록한 사람 | 그대로 |
| 손익·마진·수율·각종 비용 | 없음 | 비워서 내보낸다. ERP 파일에서도 대부분 비어 있다 |

## 3. 기록 구분

지금의 입고·출고·조정 틀은 그대로 두고, 그 아래에 구분을 고르게 한다.

| 종류 | 구분 | 재고 | ERP 로 나갈 때 |
|---|---|---|---|
| 입고 | 매입 | + | 매입생산 파일 · 매입 |
| 입고 | 생산 | + | 매입생산 파일 · 생산(보관처 있음) |
| 입고 | 반품 | + | 출고 파일 · 반품(수량 음수) |
| 출고 | 매출 | − | 출고 파일 · 매출(보관처 있음) |
| 출고 | 현장 투입 | − | 출고 파일 · 재료 |
| 이동 | 창고 → 창고 | 합계는 그대로, 보관처만 바뀜 | ERP 방식대로 옮겨 온 쪽에 생산 한 줄(적요 `○○이고`), 나간 쪽에 재료 한 줄 |
| 조정 | 실사 | ± | 내보내지 않는다 |
| 바로 출고 | 주문 생산 | 변동 없음 | 매입생산 파일 · 생산(보관처 없음) 한 줄 + 출고 파일 · 매출(보관처 없음) 한 줄 |

- 이미 쌓인 기록은 구분이 비어 있다. 추출할 때 입고는 생산, 출고는 매출로 본다(8장 결정 4).
- 재고 계산 방식은 바꾸지 않는다. 구분은 꼬리표일 뿐이다.

## 4. 화면

| 화면 | 바뀌는 것 |
|---|---|
| 입고 창 | 맨 위에 구분 [매입] · [생산] · [반품]. 매입을 고르면 단가 칸이 보인다 |
| 출고 창 | 맨 위에 구분 [매출] · [현장 투입]. 매출을 고르면 단가 칸이 보인다 |
| 이동 창(새로) | 품목과 로트를 고르고, 어디서 어디로 옮기는지 고른다 |
| 바로 출고 창(새로) | 거래처를 고르고 품목·규격·kg·단가를 줄줄이 적는다. 재고는 건드리지 않는다 |
| 재고 화면 | 보관처별로 나눠 볼 수 있게 한다(창고를 둘 이상 쓰기로 하면) |
| 히스토리 | 구분 표시, 구분별 걸러 보기, **[엑셀 추출]** |
| 칸 설정 | 보관처·단가·본선명을 켜고 끌 수 있게 한다(지금의 거래처·테잎색과 같은 방식) |

- 이 화면만 봐서는 다른 서비스가 있다는 것을 알 수 없게 한다. 칸 밑 안내 문구는 넣지 않는다.
- 추출 버튼은 관리자에게만 보인다(8장 결정 6).

### 1차 구현(2026-11-20)에서 실제로 만든 것

| 항목 | 상태 |
|---|---|
| 입고·출고 창의 구분, 단가(원/kg), 보관처 고르기 | 만듦. 단가는 매입·매출·반품에만 보인다 |
| 이동 창 | 만듦. 기록 창의 넷째 탭. 보관처가 둘 이상일 때만 보인다 |
| 보관처 목록 관리 | 만듦. 기록 창의 '칸 설정'에서 관리자가 추가·삭제 |
| 재고 화면 | 로트가 보관처별로 갈려 보인다. 기본 보관처는 이름을 붙이지 않는다 |
| 히스토리 | 구분·보관처·단가 표시, 검색에 구분·보관처 포함, [출고 엑셀]·[매입·생산 엑셀] |
| 본선명 칸 | 만들지 않음. ERP 에서도 4%만 채워져 있다. 엑셀에는 빈 칸으로 나간다 |
| 보관처·단가 칸을 켜고 끄는 설정 | 만들지 않음. 보관처는 목록이 하나면 안 보이고, 단가는 구분에 따라 보인다 |
| 히스토리의 구분별 탭 | 만들지 않음. 검색창에 구분 이름을 치면 걸러진다 |
| 옛 기록의 구분 고치기 | 만들지 않음. 추출할 때 입고 = 생산, 출고 = 매출로 본다 |
| 바로 출고(주문 생산) | 만들지 않음(결정 1) |

단가는 kg당으로 적는다. 엑셀로 나갈 때는 ERP 방식대로 단위당 단가(상자 단위면 kg당 단가 × 상자 중량)로 바뀐다.

## 5. 풀어야 할 문제

### 5-1. 주문 생산이 가장 큰 덩어리다

ERP 기록의 3분의 2(3년 5만 2천 건, 하루 약 60줄)가 "주문 받은 날 만들어 바로 나간" 것이고, pdsr.kr 에는 이걸 적는 곳이 없다. 이걸 빼면 내려받은 엑셀은 창고 입출고만 담고, 출고량의 절반이 빠진다.

넣으려면 [바로 출고] 창이 필요하다. 거래처별로 하루 수십 줄을 빠르게 적어야 하므로, 재고 기록 창보다 주문서에 가까운 화면이 된다. 누가 적을지(현장, 사무실)도 정해야 한다.

### 5-2. 규격

ERP 는 같은 품명 아래 줄마다 규격을 따로 적는다(`40g`, `녹차담은30g`, `탈피PBO-300/700` 등 2,900종). pdsr.kr 은 품목 하나에 규격 하나다.

- 창고 기록은 지금 방식대로 품목의 규격을 내보내면 된다.
- 주문 생산까지 적으려면 줄마다 규격을 적는 칸이 필요하다. 전에 적은 값을 목록으로 띄워 고르게 한다.

### 5-3. 단가와 금액

매출·매입에는 단가가 있다. pdsr.kr 은 현장 계정도 쓰는 화면이라, 단가 칸을 누구에게 보일지 정해야 한다. 단가를 빼고 수량만 내보내는 것도 방법이다([예상] 화면은 금액을 쓰지 않는다).

### 5-4. 보관처

ERP 에는 구평창고1층, 현이냉동 등 30여 곳이 있지만 97%가 구평창고1층이다. 이동을 적으려면 보관처가 둘 이상 있어야 한다. 보관처를 도입하면 재고가 "품목 × 제조일자 × 박스 중량 × 보관처"로 한 단계 더 갈린다.

## 6. 저장 구조

파도소리 번호열에 마이그레이션 하나를 더한다(`supabase/migrations/factory/011_txn_kinds.sql`).

| 대상 | 내용 |
|---|---|
| `factory.stock_txns` 에 칸 추가 | 구분, 보관처, 단가, 줄 규격, 본선명, 이동 짝 번호 |
| `factory.direct_sales` 표(새로) | 바로 출고 기록(일자·거래처·품목·규격·kg·단가). 재고에 영향 없음. 5-1 을 넣기로 할 때만 |
| `stock_lots` 뷰 | 보관처를 넣기로 하면 보관처까지 나눠 집계 |
| 저장 함수 | 새 칸을 받도록 고친다. 이동은 나간 줄과 들어온 줄을 한 번에 적는다 |

- public 스키마는 건드리지 않는다. 적용은 대표가 Supabase SQL Editor 에서 한다.
- 새 칸은 모두 비어 있어도 되게 해서, 적용 전후로 지금 화면이 그대로 돈다.

## 8. 대표 결정이 필요한 것

| 번호 | 결정할 것 | 제안 |
|---:|---|---|
| 1 | 주문 생산(바로 출고)까지 pdsr.kr 에 적을지 | **확정(11-20 대표): 창고 입출고부터.** 주문 생산은 이번에 만들지 않는다 |
| 2 | 단가·금액을 적을지, 누구에게 보일지 | **확정(11-20 대표): 모든 계정이 단가를 적는다.** 매입·매출·반품 기록에 kg당 단가 칸 |
| 3 | 보관처를 여럿으로 나누고 이동을 적을지 | **확정: 넣는다.** 기본값은 구평창고1층, 목록은 관리자가 관리. 재고는 보관처별로 갈려 보인다 |
| 4 | 이미 쌓인 기록의 구분 | **확정: 입고는 생산, 출고는 매출로 본다.** |
| 5 | ERP 는 계속 쓰는지 | 당분간 함께 쓴다고 보고, pdsr.kr 추출본은 대조·예상용으로 쓴다 |
| 6 | [엑셀 추출]을 누가 쓸 수 있는지 | **확정: 모든 계정** |

결정 1 이 범위를 가른다. 빼면 1~3단계로 끝나고, 넣으면 주문 입력 화면을 새로 만드는 일이 된다.

## 9. 이번에 하지 않는 것

- ERP 3년치 기록을 pdsr.kr 재고 기록으로 옮기는 일. [예상] 화면에는 이미 올릴 수 있다.
- 손익·마진·수율·각종 비용 칸. 빈 칸으로 내보낸다.
- ERP 에 다시 올리는 업로드용 파일. ERP 가 어떤 양식을 받는지 확인되지 않았다.
