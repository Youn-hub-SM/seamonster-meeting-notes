# 파도소리 ERP 대체 1단계 기획안 — 거래처·출고증·주문 출고

- 작성일: 2026-11-20
- 전체 그림: `docs/factory-erp-plan.md`
- 받은 자료: 출고증 실물 사진 1장, ERP 매출 입력 화면 캡처 1장. 거래처 목록은 씨몬스터와 같게 만든다(대표).
- 상태: 기획안. 대표 결정(7장) 뒤에 만든다.

## 1. 자료에서 읽은 것

### 출고증

| 자리 | 내용 | pdsr.kr 에 있는가 |
|---|---|---|
| 번호 | `20261119-0007` — 출고일 + 그날의 일련번호 | 없음 |
| 받는 곳 | `구평창고1층 貴中` — 보관처 앞으로 쓴다 | 보관처 있음(011) |
| 줄 | 품명 · 규격 · 본선명 · 적요 · 단위 · 수량 · 입고일자 | 본선명만 없음 |
| 적요 | `황 국내산` — 테잎색 + 원산지 | 있음 |
| 단위·수량 | `16KG` · 박스 수 | 있음(박스 중량 · 박스 수) |
| 입고일자 | 그 로트가 들어온 날 | 있음 |
| 계 | 박스 수 합 | 계산 |
| 본문 | "상기 품명 및 수량을 ○○에게 출고하여 주시기 바랍니다." | 거래처 있음 |
| 출고자/차량번호 | 빈 칸(손으로 적음) | 빈 칸으로 인쇄 |
| 출고일자 | 요일까지 | 있음 |
| 냉장료 문구 | 출고일 다음 날부터 출고자 부담 | 날짜만 계산 |
| 발행일자 | 날짜와 시각 | 인쇄 시각 |
| 아래 | 회사명 · 대표 · TEL · FAX · 직인 | 없음(설정으로 넣는다) |

- 출고증은 **창고에 보내는 지시서**다. 한 거래처에 보낼 로트를 줄줄이 적고, 현장이 수량에 동그라미를 치며 확인한다.
- 한 장에 줄이 12칸이다.
- 같은 품명(방어순살)이 규격별로 다른 줄이다. pdsr.kr 에서 품목 = 품명 + 규격이라 그대로 맞는다.

### ERP 매출 입력 화면

- 위쪽은 **재고 로트를 찾는 조건**이다: 품명, 규격, 단위, 원산지, 보관처, 매입처, 매입일자, 본선명, 적요.
- 그 아래에 출고일자, 매출처(코드로 찾기), 매출자, 출고구분(`일반매출`)을 적는다.
- 매출처를 고르면 **외상매출금 잔액**과 [거래원장보기], 매출한도금액이 보인다.
- 즉 ERP 는 매출을 늘 "재고 로트에서 골라" 적는다. pdsr.kr 의 출고 창과 같은 방식이다.
- 주문 받은 날 만든 물량도 ERP 에서는 먼저 생산으로 넣고, 그 로트를 골라 매출로 적는다(3년 기록에서 생산과 매출이 같은 날 같은 수량으로 짝을 이룬 이유다).

## 2. 1단계에서 만드는 것

세 부분으로 나눈다. 앞의 것부터 따로 써 볼 수 있다.

| 부분 | 내용 | 바탕 |
|---|---|---|
| 가. 거래처 목록 | 매출처·매입처를 등록하고, 기록 창에서 목록에서 고른다 | 씨몬스터 거래처와 같은 칸 |
| 나. 출고 번호와 출고증 인쇄 | 출고를 저장하면 번호가 붙고, 출고증을 뽑는다 | 지금의 출고 창 |
| 다. 바로 출고 | 그날 만든 물량을 생산 → 매출 두 번 적지 않고 한 번에 적는다 | 새 입력 창 |

거래명세서는 실물을 받은 뒤 따로 기획한다(8장).

## 3. 가. 거래처 목록

씨몬스터 거래처와 같은 칸을 쓴다.

| 칸 | 비고 |
|---|---|
| 업체명 | 필수 |
| 사업자등록번호 · 대표자명 | |
| 담당자명 · 담당자 연락처 · 담당자 이메일 | |
| 주소 | |
| 결제조건 | 예: 월말정산 |
| 메모 | |
| 구분 | 매출처 · 매입처 · 둘 다. 파도소리에만 더한다 |

- 메뉴에 **[거래처]** 를 더한다. 목록, 검색, 등록, 수정.
- 지금까지 기록에 자유 입력으로 적힌 거래처 이름을 모아 한 번에 등록하는 버튼을 둔다. 같은 곳이 다른 표기로 적힌 것은 사람이 합친다.
- 기록 창의 거래처 칸은 목록에서 고른다. 목록에 없으면 그 자리에서 이름만 넣어 바로 등록할 수 있게 한다(품목의 "새 품목으로 입고"와 같은 방식).
- 씨몬스터 거래처 화면의 사업자등록증 사진 읽기(AI)는 넣지 않는다. 필요하면 나중에 붙인다.
- 씨몬스터의 거래처와 표를 따로 둔다. 파도소리 화면에서 씨몬스터 자료가 보이면 안 된다.

## 4. 나. 출고 번호와 출고증

### 출고 한 건

- 출고 창에서 [출고 저장]을 한 번 누른 것이 출고 한 건이다(거래처 하나, 출고일 하나, 로트 여러 줄).
- 저장하면 `출고일-일련번호`(예: `20261120-0003`)가 붙는다. 일련번호는 그 출고일에 저장한 순서다.
- 구분이 **매출**인 출고에만 번호를 붙인다. 현장 투입과 이동에는 붙이지 않는다.

### 출고증

- 저장 직후 화면과 히스토리의 그 출고 줄에 **[출고증]** 버튼을 둔다. 누르면 인쇄 창이 열린다.
- 한 건에 보관처가 둘이면 보관처마다 한 장으로 나눈다(받는 곳이 보관처이기 때문이다).
- 줄이 12개를 넘으면 다음 장으로 넘긴다.
- 양식은 실물과 같게 한다: 제목, 번호, 받는 곳, Tel·Fax, 표 7열, 계, 본문, 출고자/차량번호, 출고일자와 요일, 냉장료 문구, 발행일자, 회사명·대표·TEL·FAX.
- 회사 정보(상호, 대표, 전화, 팩스, 로고, 직인 그림)는 관리자가 한 번 넣어 두는 설정으로 둔다.
- 다시 뽑아도 번호는 그대로다. 출고를 취소하면 그 번호는 비워 둔다(당겨 쓰지 않는다).

### 본선명

출고증에 본선명 열이 있다. 지금 기록에는 이 칸이 없다. 입고 줄에 선택 칸으로 넣고, 출고증에는 그 로트의 값을 보여준다(8장 결정 4).

## 5. 다. 바로 출고

그날 만들어 그날 나가는 물량이다. ERP 에서는 생산 입력과 매출 입력을 따로 한다.

- 메뉴 재고 화면에 **[바로 출고]** 를 더한다.
- 날짜와 거래처를 고르고, 줄마다 품목 · 박스 중량 · 박스 수 · kg · 단가를 적는다.
  - 품목을 고르면 그 거래처에 마지막으로 보낸 단가가 채워진다.
  - 엑셀에서 복사한 여러 줄을 붙여 넣을 수 있게 한다(하루 약 60줄).
- 저장하면 "생산해서 바로 매출한 기록"으로 남는다. **창고 재고는 바뀌지 않는다.**
- 출고증은 뽑지 않는다(창고에서 꺼내는 것이 아니다). 번호는 같은 체계로 붙인다. 거래명세서에는 창고 출고와 함께 나온다.
- ERP 양식 엑셀로 내려받으면 보관처가 빈 생산 한 줄과 매출 한 줄로 나간다.

규격은 품목에 딸려 있다. 주문마다 규격이 다르면 품목을 규격별로 등록해야 한다. ERP 에는 규격 표기가 2,900종이라, 줄마다 규격을 따로 적게 할지는 써 보면서 정한다(8장 결정 5).

## 6. 저장 구조

파도소리 번호열에 마이그레이션 하나를 더한다(`supabase/migrations/factory/012_partners_docs.sql`).

| 대상 | 내용 |
|---|---|
| `factory.partners` 표 | 거래처(3장의 칸) |
| `factory.out_docs` 표 | 출고 한 건(번호, 출고일, 거래처, 종류: 창고 출고·바로 출고, 저장한 사람) |
| `factory.direct_sales` 표 | 바로 출고의 줄(출고 건, 품목, 박스 중량, 박스 수, kg, 단가) |
| `factory.stock_txns` 에 칸 추가 | 출고 건 번호, 거래처 번호, 본선명 |
| 번호를 매기는 함수 | 출고일마다 일련번호를 겹치지 않게 준다 |
| 설정 | 회사 정보(상호·대표·전화·팩스·로고·직인) |

- public 스키마는 건드리지 않는다. 적용은 대표가 Supabase SQL Editor 에서 한다.
- 기존 기록의 거래처 이름(글자)은 그대로 둔다. 거래처 번호는 새 기록부터 붙고, 옛 기록은 "모아 등록" 때 이름으로 잇는다.

## 7. 만드는 순서

| 순서 | 내용 | 확인 방법 |
|---|---|---|
| 1 | 거래처 목록 화면, 기록 창에서 고르기 | 베타에서 등록·수정·고르기 |
| 2 | 출고 번호, 출고증 인쇄, 회사 정보 설정 | 실물 출고증과 나란히 놓고 비교 |
| 3 | 바로 출고 | 하루치 주문을 넣어 보고 ERP 입력과 걸린 시간 비교 |
| 4 | ERP 양식 엑셀에 바로 출고 반영 | 내려받아 [예상]에 올려 "그날 생산" 물량이 잡히는지 확인 |

1과 2는 크지 않다. 3이 가장 크다.

## 8. 대표 결정이 필요한 것

| 번호 | 결정할 것 | 제안 |
|---:|---|---|
| 1 | 만드는 범위 | 가·나를 먼저 만들어 써 보고, 다를 이어서 |
| 2 | 거래처 칸 | 목록에서 고르되, 없으면 그 자리에서 이름만 넣어 등록 |
| 3 | 출고증의 로고와 직인 | 그림 파일을 받아 넣는다. 없으면 빈 자리로 두고 도장을 찍는다 |
| 4 | 본선명 | 입고 줄에 선택 칸으로 넣는다 |
| 5 | 바로 출고의 규격 | 품목에 딸린 규격을 쓴다. 써 보고 모자라면 줄 규격 칸을 더한다 |
| 6 | 출고구분 | ERP 에 `일반매출` 말고 어떤 종류가 있는지 알려 주시면 맞춘다 |
| 7 | 외상매출금 표시 | 3단계(미수금)에서 넣는다. 1단계 화면에는 없다 |

| 항목 | 상태 |

| 본선명 | 만듦. '칸 설정'에서 켜면 입고 줄에 칸이 보인다(기본 꺼짐) |

## 9. 아직 받지 못한 자료

- 거래명세서 실물. 받으면 이 문서에 이어서 기획한다.
- ERP 매출 입력 화면의 아래쪽(로트 목록과 저장 버튼 부분). 받은 캡처는 위쪽 조건 부분만 보인다.
- 출고증의 로고와 직인 그림 파일.
