# 급여·연차 관리 툴 기획안

- 작성일: 2026-11-20 (같은 날 2차 수정: 주민등록번호 입력·인사대장·시급제·근무대장 반영)
- 상태: 2026-11-20 대표 "제안대로 실행" — 9장의 제안이 그대로 결정이다. 1단계(전용 창·인사대장·요율)는 베타에서 대표 확인(dev 4a83e70, 10장). 2단계(근무대장) 구현(11장). 2026-11-21 대표 "3단계 급여 계산을 시작해. 남은 단계도 다 넣어줘" — 3단계(급여, 12장)·4단계(연차, 13장) 구현. 1·2단계는 11-21 운영 배포, 주소는 `pdsr.kr/hr`.
- 참고: 급여 = 페이존(급여명세서·급여대장·인사기록카드 구성)과 국내 급여 프로그램 공통 계산법, 연차 = 시프티(휴가 발생 규칙·수동 발생·발생 건 단위 관리)
- 숫자의 출처: 2026-11-20 검색으로 확인한 값이다. 대부분 급여 프로그램 공지·기사 같은 2차 자료라, 만들 때 공단 고시·국세청·고용노동부 원문과 한 번 더 대조한다(8장).

## 1. 한 줄 요약

업무도우미와 같은 Vercel·Supabase 위에, **업무도우미 로그인과 완전히 따로 잠긴 창** 하나를 만든다. 그 안에서 인사대장(주민등록번호 포함) → 근무대장(일한 날짜·시간) → 시급 기준 월 급여 계산(주휴·가산수당, 4대보험·소득세 자동) → 급여대장·급여명세서 인쇄, 그리고 연차 자동 발생·수동 추가·사용 기록·잔여 확인을 한다.

## 2. 접근 통제 — 창 자체를 따로 둔다

대표 말: "지정한 비번만 들어갈 수 있어야 한다. 오류조차 허용하지 않도록 창 자체를 별도로."
이렇게 읽었다: 파도소리처럼 업무도우미 일반 계정과 섞이지 않는 별도 계정으로 두고, 대표가 정한 비밀번호만 통과시키며, 업무도우미 쪽에 실수나 버그가 생겨도 급여 창은 열리지 않게 한다. 다르게 읽었으면 9장 1번에서 바로잡아 주면 된다.

| 겹 | 내용 | 막는 것 |
|---|---|---|
| 전용 로그인 화면 | `/hr/login`. 업무도우미에 관리자로 로그인해 있어도 급여 창은 비밀번호를 따로 넣어야 열린다 | 업무도우미 로그인만으로 들어오는 것 |
| 전용 쿠키·전용 서명 키 | 쿠키 `hr_auth`, 서명 키 `HR_SECRET`(업무도우미 키와 다른 값). 업무도우미·파도소리 토큰으로는 서명이 맞지 않아 통과할 수 없다 | 업무도우미 인증 코드의 버그가 급여 창으로 번지는 것 |
| 지정 비밀번호만 | 허용 비밀번호는 Vercel 환경변수 `HR_USERS`("이름:비번,…")에만 둔다. 화면에서 계정을 만드는 기능을 아예 두지 않는다 | 계정 관리 화면의 실수·버그로 계정이 생기는 것 |
| API 이중 검사 | 미들웨어가 한 번, `/api/hr/*` 각 경로가 한 번 더 `hr_auth` 를 직접 검증한다 | 미들웨어 설정 실수 하나로 뚫리는 것 |
| 데이터 분리 | Supabase 새 스키마 `hr`. public 에 급여 표를 두지 않는다. AI 비서 조회 차단 정규식에 `hr` 추가, 루커 계정에 권한 없음 | AI 비서·커스텀 리포트·루커로 급여가 조회되는 것 |
| 주민등록번호 암호화 | DB 에는 암호문만 저장한다(AES-256, 키는 환경변수 `HR_DATA_KEY`). 3-1 참조 | DB 가 통째로 새도 주민등록번호가 읽히는 것 |
| 흔적 없음 | 업무도우미 사이드바·홈·전역 검색·사용 가이드·업데이트 노트·활동 기록(activity_log)에 급여 창을 올리지 않는다. 기록은 `hr` 안의 자체 이력에만 | 메뉴·검색·GPT 가 읽는 업데이트 노트로 존재나 금액이 새는 것 |
| 짧은 세션 | 로그인 12시간 뒤 만료, 자동 연장 없음. 비밀번호 5번 틀리면 15분 잠금 | 켜 둔 PC, 비밀번호 찍어 보기 |

- 업무도우미 계정(관리자 포함)·파도소리 계정은 `/hr` 에 들어올 수 없고, 급여 창 로그인으로는 업무도우미·파도소리 화면에 들어갈 수 없다(쿠키가 서로 달라 구조상 그렇다).
- 비밀번호를 바꾸거나 사람을 빼려면 환경변수를 고치고 다시 배포한다. 전원 즉시 로그아웃은 `HR_SECRET` 교체.
- 공용 파일 `middleware.ts` 에 `/hr` 분기 하나를 넣어야 한다(다른 세션에 알리고 최소로).
- 직원이 본인 것만 보는 '직원 확인 링크'(`/me/<토큰>`, 2026-11-21)는 이 창의 로그인 밖에 따로 둔 길이다 — 17장.

## 3. 인사대장

### 3-1. 주민등록번호

- 직원 등록 때 주민등록번호(외국인은 외국인등록번호)를 입력한다. 원천징수·4대보험 신고에 쓰는 번호라 법령상 수집 근거가 있고, 대신 **암호화 저장이 의무**다.
- 저장: 서버에서 암호화한 값만 DB 에 넣는다. 키 `HR_DATA_KEY` 는 Vercel 환경변수에만 있다. **키를 잃으면 번호를 되살릴 수 없으므로** 대표가 키를 따로 보관한다.
- 화면: 기본은 뒷자리 가림(`900101-1******`). [번호 보기]를 누르면 전체가 보이고, 누가 언제 봤는지 이력에 남는다.
- 인쇄·엑셀: 인사대장을 뽑을 때 '주민등록번호 전체 / 가림'을 고른다. 기본은 가림.
- 번호에서 생년월일·성별·만 나이를 자동으로 뽑아 쓴다(국민연금 만 60세, 고용보험 만 65세 판정, 명세서의 생년월일).
- 입력 때 자릿수·날짜·검증 숫자를 확인한다. 2020년 10월 이후 출생자는 검증 숫자가 맞지 않을 수 있어 경고만 한다.

### 3-2. 화면

| 화면 | 내용 |
|---|---|
| 인사대장 | 재직·퇴사 직원 목록. 사번·성명·주민등록번호(가림)·입사일·부서·직위·시급·연락처. A4 가로 인쇄, 엑셀 |
| 인사기록카드 | 한 사람 한 장. 아래 칸 전부. 인쇄 |

직원 한 명의 칸
- 기본: 사번, 성명, 주민등록번호, 주소, 연락처, 비상 연락처
- 고용: 입사일, 퇴사일·퇴사 사유, 부서, 직위, 맡은 업무, 고용 형태, 계약 기간(정한 경우), 이력(학력·경력) 메모
- 근로 조건: 급여 형태(시급/월급), 시급, 소정근로(일하기로 한 요일, 하루 시간) — 주휴수당·연차 계산의 기준
- 세금·보험: 공제대상가족 수(본인 포함), 8~20세 자녀 수, 원천징수 비율(80/100/120%), 4대보험별 가입 여부, 국민연금 기준소득월액·건강보험 보수월액
- 지급: 은행·계좌번호·예금주

근로기준법의 근로자 명부 기재사항(성명·성별·생년월일·주소·이력·업무·고용일·계약 기간·퇴직일과 사유)을 모두 담는다. 퇴사자는 지우지 않고 '퇴사'로 둔다(명부는 퇴직 뒤 3년 보존).

## 4. 근무대장

급여가 시급 기준이므로, 급여 계산의 원천은 근무대장이다.

### 4-1. 입력

- 한 직원의 한 달을 한 표로 본다. 한 줄 = 하루.
- 한 줄의 칸: 날짜, 종류, 출근 시각, 퇴근 시각, 휴게(분), 근무 시간, 비고.
- 출근·퇴근·휴게를 넣으면 근무 시간과 야간(22:00~06:00) 시간이 자동으로 나온다. 시각 없이 **근무 시간만 숫자로** 적어도 된다(이때 야간 시간은 따로 적는다).
- 종류: 근무 / 휴일 근무 / 유급 휴일 / 연차·반차 / 결근 / 무급 휴무. 연차는 연차 화면의 [사용 등록]과 같은 기록이다(한쪽에 넣으면 다른 쪽에 보인다).
- 평소 근무 시간(예: 09:00~18:00, 휴게 60분)을 직원 정보에 두고 [평소대로 채우기]로 한 달을 채운 뒤 다른 날만 고친다.
- 월 합계: 근무 일수, 총 근무 시간, 연장·야간·휴일 시간, 주별 소계와 주휴 대상 여부.
- 개인별 월 근무대장 인쇄, 엑셀.
- 그달 급여가 확정되면 그달 근무대장도 잠긴다.

### 4-2. 근무대장 → 급여

| 항목 | 계산 |
|---|---|
| 기본급 | 근무 시간 합 × 시급 |
| 주휴수당 | 그 주 소정근로 15시간 이상이고 소정근로일에 결근이 없으면 하루치. 주 40시간이면 8시간 × 시급, 그보다 짧으면 (주 소정근로시간 ÷ 40) × 8 × 시급 |
| 연장수당 | 하루 8시간 또는 주 40시간을 넘은 시간 × 시급 × 0.5 가산 |
| 야간수당 | 22:00~06:00 근무 시간 × 시급 × 0.5 가산 |
| 휴일근로수당 | 휴일 근무 8시간까지 × 0.5 가산, 8시간 넘은 시간 × 1.0 가산 |
| 유급 휴일·연차 | 하루 소정근로시간 × 시급 |

- 연장·야간·휴일 가산은 상시 근로자 5인 이상 사업장에만 의무다. 사업장 설정의 '가산수당 적용' 스위치로 켜고 끈다. 주휴수당은 5인 미만에도 적용된다.
- 주는 월요일~일요일로 센다(설정). 달이 바뀌는 주의 주휴수당은 그 주가 끝나는 달 급여에 넣는다(설정).
- 자동으로 나온 수당 금액은 월 급여 화면에서 손으로 고칠 수 있고, 고친 값은 표시가 남는다.
- 시급이 최저임금(2026년 10,320원, 2027년 10,700원)보다 낮으면 경고한다.
- 월급제 직원이 있으면 근무대장 없이 고정 금액으로 계산한다(같은 화면, 급여 형태만 다름).

## 5. 급여

### 5-1. 화면

| 화면 | 하는 일 |
|---|---|
| 급여 항목 | 지급 항목(기본급·주휴수당·연장·야간·휴일·식대·자가운전·보육수당·상여·연차수당·기타)과 공제 항목. 항목마다 과세/비과세·비과세 한도·매월 고정/그때 입력 |
| 월 급여 | 귀속월·지급일 선택 → 근무대장에서 시간·수당 자동 계산 → 고정 항목 채움 → 그달 항목 입력 → 공제 자동 계산 → [확정](잠금). 확정 뒤 고치려면 [확정 취소], 고친 이력이 남는다 |
| 급여대장 | 그 달 전 직원 한 표(근로일수·근로시간·연장·야간·휴일 시간, 지급·공제·실수령, 아래에 회사 부담 4대보험 합계). A4 가로 인쇄, 엑셀. 법정 임금대장 기재사항을 채운다 |
| 급여명세서 | 한 사람 한 장(또는 한 장에 두 명·절취선). 한 명씩 또는 전원 한 번에 인쇄. PDF 는 인쇄 창의 'PDF 로 저장' |
| 요율 | 적용 시작월별 요율표·최저임금. 급여를 계산할 때 그 귀속월에 유효한 값을 쓴다 |

급여명세서에는 법정 기재사항을 모두 넣는다: 성명·생년월일(또는 사번), 임금 지급일, 임금 총액, 항목별 금액, 계산 방법(근무 176시간 × 시급 10,320원, 연장 12시간 × 시급 × 0.5 같은 식), 공제 항목별 금액과 공제 총액, 실수령액. 명세서에 주민등록번호는 찍지 않는다.

| 비과세 | 과세 급여에서 뺀다 | 식대 월 20만, 자가운전보조금 월 20만(본인 차량), 보육수당 6세 이하 자녀 1명당 월 20만(2026.1 지급분부터) |

- 보험료·세액은 10원 미만을 버린다.
- 시급제는 매달 급여가 달라진다. 국민연금·건강보험은 **공단 고지 기준**(직원 정보에 적은 기준소득월액·보수월액으로 매달 같은 금액, 고지서와 맞는다)을 기본으로 하고, 직원별로 **그달 급여 기준**을 고를 수 있다. 고용보험과 소득세는 늘 그달 급여로 계산한다.
- 만 60세 이상(국민연금 제외), 만 65세 이후 고용(고용보험 실업급여 제외), 월 60시간 미만 근로자는 직원별 가입 스위치로 처리한다. 나이에 걸리면 화면이 알려 준다.
- 연 1회 정산(건강보험 4월 정산, 연말정산 환급·추징)은 계산하지 않고, 받은 금액을 그달 '정산' 칸에 적는다.
- 간이세액표는 국세청 원본 표를 데이터로 넣어 그대로 찾는다(산식으로 흉내 내지 않는다).
- 내년 값: 최저임금 10,700원, 건강보험 7.19% 동결, 장기요양 0.9994%(건강보험료의 13.90%)로 결정됐다. 국민연금은 법에 따라 2027년 10.0%로 오른다(고시 확인 필요). 요율표가 적용 시작월로 관리되므로 2027년 1월분을 미리 넣어 둔다.

## 6. 연차

### 6-1. 발생 규칙

회사 기본값을 입사일 기준·회계연도 기준 가운데 고르고, 직원별로 다르게 지정할 수 있다.

| 구간 | 입사일 기준 | 회계연도 기준 |
|---|---|---|
| 입사 1년 미만 | 1개월 개근마다 1일(최대 11일), 입사 1년 되는 날 소멸 | 같다 |
| 첫 번째 연차 | 입사 1주년에 15일 | 다음 회계연도 첫날에 15일 × (입사일~회계연도 말 재직일수 ÷ 365). 소수점은 0.5 단위 올림(설정) |
| 그 뒤 | 입사 기념일마다 15일 + 가산 | 회계연도 첫날마다 15일 + 가산 |
| 가산 | 근속 3년부터 2년마다 1일, 최대 25일 | 같다(연수는 회계연도로 센다) |
| 유효 기간 | 발생일부터 1년 | 그 회계연도 말까지 |
| 퇴사 정산 | — | 입사일 기준으로 다시 계산해 회계연도 기준이 적으면 차이를 표시(직원에게 불리하면 안 된다) |

- 회계연도 첫날은 설정값(기본 1월 1일).
- **개근·출근율은 근무대장으로 판정한다.** 그달 소정근로일에 결근이 없으면 개근(1년 미만 월 1일 발생), 1년 출근율 80% 이상이면 15일. 연차·유급 휴일은 출근으로 센다. 판정 결과는 발생 전에 화면에 보여 주고 고칠 수 있다.
- 주 소정근로 15시간 미만 직원은 연차·주휴 대상이 아니다. 주 40시간보다 짧게 일하는 직원은 소정근로시간에 비례해 시간 단위로 계산한다(풀타임 일수 × 주 소정근로시간 ÷ 40 × 8시간).

## 10. 1단계 구현 기록 (2026-11-20)

만든 것
- 전용 창: `middleware.ts` 의 `/hr` 분기, `app/lib/hr-auth.ts`(쿠키 `hr_auth`·12시간·서명 키 `HR_SECRET`·계정 `HR_USERS`), `app/api/hr/auth`(로그인·15분 5회 잠금), `app/hr/login`, `app/hr/HrShell.tsx`, 전용 아이콘.
- 인사대장: `/hr`(목록·인쇄·엑셀), `/hr/employees/[id]`(인사기록카드·번호 보기·임금 이력), 직원 등록·수정 창. 주민등록번호 암호화 `app/lib/hr-crypto.ts`.
- 요율 `/hr/rates`, 사업장 `/hr/settings`.
- DB: `supabase/migrations/hr/001_hr_init.sql`(사업장·인사대장·임금 이력·요율·이력·로그인 시도), `supabase/migrations/176_run_report_block_hr.sql`(AI 비서 차단).

계획에서 달라진 것
- 간이세액표는 3단계(급여 계산)로 옮겼다. 국세청 원본 파일을 받아야 한다.
- 임금을 직원 칸이 아니라 적용 시작일별 이력(`hr.wages`)으로 뒀다. 시급을 올려도 지난달 급여가 바뀌지 않는다.
- 급여 창 비밀번호가 업무도우미·파도소리 계정의 비밀번호와 같으면 로그인을 거절한다.
- `/hr`·`/api/hr` 는 주소가 `.json`·`.png` 로 끝나도 미들웨어를 탄다(다른 구역은 그런 주소에서 미들웨어를 건너뛴다).
- 파도소리 주소(pdsr.kr)에서도 `/hr`·`/api/hr` 를 연다(2026-11-21). `middleware.ts` 의 파도소리 주소 분기는 `/factory` 밖 경로를 전부 `/factory` 로 돌려보내는데, 급여 창 경로만 빼고 아래 hr 분기로 넘긴다. 잠금은 그대로 `hr_auth` 하나다(파도소리 계정으로는 못 들어온다). 쿠키는 주소마다 따로라 pdsr.kr 에서 한 로그인은 업무도우미 주소에 통하지 않는다.

대표가 할 일(이것이 끝나야 베타에서 쓸 수 있다)
1. Vercel 환경변수 3개를 Production·Preview 양쪽에 같은 값으로 넣는다.
   - `HR_SECRET`: 아무 긴 문자열(16자 이상). 만들기 `node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`
   - `HR_USERS`: `이름:비밀번호,이름:비밀번호`. 비밀번호 8자 이상, 업무도우미·파도소리에서 쓰는 비밀번호와 달라야 한다.
   - `HR_DATA_KEY`: 주민등록번호 암호화 키. 만들기 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. **따로 적어 보관한다. 잃으면 저장된 번호를 되살릴 수 없고, 중간에 바꾸면 그전에 저장한 번호를 못 읽는다.**
2. Supabase SQL Editor 에 `hr/001_hr_init.sql`, `176_run_report_block_hr.sql` 을 차례로 붙여 넣고 Run.
3. Supabase Dashboard > Settings > API > Exposed schemas 에 `hr` 추가.
4. 요율 화면의 값이 고시·법령 원문과 맞는지 보고 [원문 확인]을 누른다(지금은 모두 '확인 전').

확인한 것(로컬)
- 로그인 없이 `/hr` 화면 → 로그인으로, `/api/hr/*` 11개 요청 → 401. 업무도우미 쿠키·위조 쿠키로도 401.
- 급여 창 쿠키로 `/b2b`·`/factory`·업무도우미 API → 각자의 로그인·401.
- 틀린 비밀번호 5번 뒤 잠금, 다른 주소는 안 잠김, 로그아웃 뒤 401.
- 주민등록번호 검증·가림·암호화 왕복·변조 감지·키 없으면 거절, 세션 만료·서명 키 교체·계정 삭제 시 끊김 — 단위 확인 72건.
- 입력 검증 오류 문장, 화면 모양(가짜 응답으로: 목록·등록 창·인사기록카드·요율·사업장·인쇄 창·모바일).

확인하지 못한 것

  · **올리는 양식 = 내려받는 양식.** [엑셀 내려받기]로 받은 파일을 고쳐 그대로 올릴 수 있다(칸 이름으로 찾으므로 순서가 바뀌거나 칸이 빠져도 된다).
  · 미리보기는 아무것도 저장하지 않는다. 등록할 때 서버가 **파일을 다시 읽어 다시 대조**한다 — 화면이 보낸 미리보기 결과를 저장하는 길이 없다.
  · 오류가 있는 줄은 넣지 않고 나머지를 넣는다. 다시 올려도 같은 줄은 '같음'으로 지나간다(두 번 들어가지 않는다).
  · 검증은 화면 입력과 같은 함수(`parseEmployeeInput`·`normalizeLog`)로 한다. 새 표·마이그레이션 없음. 파일은 3MB·.xlsx 만.

**인사대장**
- 한 줄 = 한 사람. 이미 있는 직원은 같은 사업장에서 **주민등록번호 → 사번 → (성명 + 입사일)** 순으로 찾아 고치고, 없으면 새로 등록한다.
- **빈 칸은 건드리지 않는다**(지우려면 화면에서). 가려진 번호(900101-1******)도 건드리지 않는다. 주민등록번호는 화면 입력과 똑같이 암호화해서만 저장하고, 미리보기·이력·로그에 싣지 않는다.
- 새 직원에 꼭 넣는 칸: 성명·입사일·시급(월급제는 월급). 나머지는 직원 등록 창과 같은 기본값.
- 임금: 금액이 지금과 다를 때만, 그리고 **'임금 적용 시작일'이 있을 때만** 고친다(언제부터인지 모르는 인상은 넣지 않고 경고). 날짜가 지금 줄과 같으면 '그날부터의 금액이 바뀐다'고 경고한다.
- 지키는 것: 남이 쓰는 사번, 번호와 사번이 서로 다른 사람을 가리키는 줄, 같은 이름이 둘 이상인데 가릴 칸이 없는 줄, 파일 안의 같은 사람 두 줄은 오류. 새로 등록할 사람이 다른 사업장에 이미 있으면 경고한다(사업장 칸 없이 섞어 올려 같은 사람이 두 번 생기지 않게).
- 내려받는 인사대장에 칸 셋을 더했다: 임금 적용 시작일·보험 기준·연차 기준(올릴 때 필요한 칸이 내려받는 파일에 없으면 왕복이 안 된다). 칸 목록은 `app/lib/hr-import.ts` 한 곳.

**근무대장**(화면의 그 달만)
- 양식 = 그 달의 [엑셀 내려받기] 파일(직원마다 한 시트). 한 시트에 날짜·사번·성명·출근·퇴근 칸을 둔 목록도 읽는다.
- **파일에 있는 날짜만 넣거나 고친다.** 파일에 없는 날, 내용을 비운 줄은 저장된 그대로 둔다 — 엑셀을 올려서 지워지는 날은 없다.
- 종류를 비우고 출근·퇴근만 적으면 '근무'. 휴게(분)를 비우면 직원 정보의 평소 휴게(저장된 줄과 출퇴근이 같으면 그 줄의 휴게). 야간을 비우면 다시 계산하되, 출퇴근·휴게가 저장된 줄과 같으면 손으로 고쳐 둔 야간을 지킨다. 비고를 비우면 저장된 비고를 지킨다.
- 급여가 확정된 달, 입사 전·퇴사 뒤 날짜, 그 달에 재직하지 않은 사람, 같은 날 두 번은 넣지 않는다. 다른 달의 줄은 세어서 알려 주고 넣지 않는다.
- 저장은 직원마다 한 달을 한 번에(`hr.save_work_logs`) — 저장된 줄 위에 올린 줄을 덮어 그 달 전체를 보낸다.

파일: `app/lib/hr-import.ts`(순수: 칸 읽기·시트 해석)·`hr-import-db.ts`(대조·저장), `app/api/hr/employees/import`·`app/api/hr/work-logs/import`, `app/hr/ExcelImport.tsx`(두 화면 공용 창). 이력: `employee_import`·`work_import` + 직원별 `employee_create`·`employee_update`·`work_save`(detail.via = excel).

확인한 것
- 가짜 DB(메모리 표)에 **실제 .xlsx 파일을 만들어 올리는** 대조 72건: 칸 읽기(엑셀 날짜·시각 칸, 숫자로 든 주민등록번호, 쉼표 숫자), 새 등록·고침·같음·오류, 미리보기가 아무것도 쓰지 않음, 같은 파일 다시 올리기, **내려받은 파일(가린 번호·전체 번호)을 그대로 올리면 모두 '같음'**, 빈 칸·가려진 번호가 그대로 남음, 임금 줄 추가·경고, 이력에 번호·계좌 값이 없음, 근무대장 채워 올리기·목록 모양·확정된 달·없는 날이 지워지지 않음.
- 화면은 가짜 응답으로(두 화면의 창·미리보기·등록·일부 실패), 타입 검사, 운영 빌드(빌드 뒤에 넣은 '다른 사업장 경고' 세 줄은 타입 검사와 대조로만 확인).

확인하지 못한 것
- **실제 DB 로는 올려 보지 못했다.** 특히 대표가 쓰던 기존 엑셀(이 창의 양식이 아닌 파일)은 칸 이름이 달라 그대로는 읽히지 않을 수 있다 — 그 파일의 칸 이름을 알려 주면 읽는 이름을 더한다.
- 한글 엑셀·한셀에서 저장한 파일, 아주 큰 파일(수천 줄).

## 19. 소속 (2026-11-21)

대표: "소속 필드를 넣어줘. 한 회사에 여러 소속이 있어. 지금은 파도소리, 엄마와 바다 가 있어."
- **소속 = 한 회사(사업장) 안의 사업 단위.** 부서와 다른 칸이다(소속 파도소리 · 부서 생산팀).
- 사업장마다 소속 목록을 둔다: [사업장] › [사업장 수정] › '소속(쉼표로 나눠 적기)'. 직원 등록·정보 수정 창에서 그 가운데 하나를 고른다(사업장 다음 칸).
  · 소속 목록이 빈 사업장은 직원 화면에 소속 칸이 아예 보이지 않는다 — 소속을 쓰지 않는 회사에는 달라지는 것이 없다.
  · 사업장을 바꾸면 소속은 비운다(목록이 사업장마다 다르다).
- 보이는 곳: 인사대장(소속 열 · '모든 소속' 고르기 · 검색 · 인쇄 · 엑셀 내려받기도 고른 소속만), 인사기록카드, 증명서의 '소속'(사업장 · 소속 · 부서를 이어 찍는다), 엑셀 내려받기·올리기의 '소속' 칸.
  근무대장·급여·통계에서 소속별로 보는 것은 2026-11-22 에 더했다(23장). 연차 창은 그대로다.
- 소속은 **이름(글자)** 으로 직원에 들어간다. 목록에서 이름을 지우거나 바꿔도 그 소속이던 직원의 값은 옛 이름으로 남고, 화면이 '(목록에 없음)'으로 보여 준다. 엑셀 올리기는 목록에 없는 소속 이름을 경고한다(오타로 소속이 하나 더 생기지 않게).
- DB: migration **hr/006** — `hr.workplaces.affiliations text[]`, `hr.employees.affiliation text`. 사업장이 하나뿐이고 목록이 비어 있으면 '파도소리', '엄마와 바다'를 넣어 둔다(둘 이상이면 어느 회사의 소속인지 알 수 없어 넣지 않는다 — [사업장 수정]에서 직접).
- **hr/006 을 적용하기 전에도 멈추지 않는다.** 읽기는 소속 칸 없이 다시 읽고(소속은 빈 값), 쓰기는 소속이 빈 값이면 그 칸을 빼고 쓰며, 소속을 넣으려는 저장만 'DB 준비 전(hr/006)'으로 거절한다 — 넣은 소속이 조용히 사라지지 않게. (`readEmployees`·`writeEmployee`, 사업장은 route 안의 `read`·`write`)
- 직원 확인 링크(/me)의 화면에는 넣지 않았다.

확인한 것
- 가짜 DB 로 **적용한 DB 와 적용 전 DB 두 상황** 대조 33건: 소속 목록 저장·검사, 직원 등록·수정·비우기·이력, 내려받기(소속 칸·소속 골라 받기), 올리기(바뀌는 칸·목록에 없는 이름 경고·그대로 올리면 같음), 적용 전에는 인사대장·카드·사업장·내려받기가 그대로 열리고 소속을 넣는 저장만 거절.
- 앞의 대조(엑셀 올리기 72건 · 직원 링크 92건) 그대로 통과. 화면은 가짜 응답으로(인사대장 열·고르기, 등록 창, 인사기록카드, 사업장 창, 증명서). 타입 검사, 운영 빌드.

확인하지 못한 것
- **SQL(hr/006)을 실제로 실행해 보지 못했다.** 적용 전 오류 문장은 PostgREST 의 문장('column … does not exist', "Could not find the '…' column … in the schema cache")을 본떠 시험했다 — 실제 문장이 다르면 적용 전 화면이 'DB 준비 전'으로 멈출 수 있으니, 배포보다 SQL 을 먼저 적용하는 편이 안전하다.

## 20. 표 모양 (2026-11-21)

대표(다른 서비스의 표 그림과 함께): "표 레이아웃을 이런식으로 수정하자. 연한 선으로 필드를 나누고 필드 아래에 중앙 정렬로 숫자를 넣고."
- **급여 창의 목록·요약 표(`.hr-table`)만** 이렇게 그린다: 표 둘레 테두리(모서리 8), 머리 줄에 옅은 바탕, 칸 사이 연한 세로선, 줄 사이 연한 가로선, **숫자 칸(`.num`)은 머리도 값도 칸 가운데**. 글자 칸은 왼쪽 그대로.
  적용되는 표: 인사대장, 근무대장 목록, 급여 목록, 연차(목록과 펼친 표), 급여 항목, 요율, 간이세액표, 사업장, 통계.

- **업무도우미의 표 기준은 그대로다**(숫자 값은 오른쪽·머리는 왼쪽 — docs/design-system.md, 2026-08-28·10-14 대표). 이 모양은 `app/hr/hr.css` 한 곳의 규칙이고 `b2b.css` 는 손대지 않았다.
- 확인: 근무대장 목록·인사대장·표 안의 표(연차 펼침 구조)를 화면에서 봤다(가짜 응답). 급여·통계·요율 화면은 같은 규칙이 걸리지만 따로 열어 보지는 못했다.

## 21. 연차 창의 직원 찾기 (2026-11-21)

- 확인: 화면(가짜 응답)에서 이름·초성·생년월일 세 모양·사번·섞어 치기·없는 값, 고른 직원이 저장 요청에 실리는 것, 두 창. 타입 검사, 운영 빌드.

## 22. 공휴일 (2026-11-22)

대표: "소속별 보기와 공휴일 자동반영은 바로 진행하고 배포바람."
- **공휴일 목록이 DB 에 있다(`hr.holidays`, migration hr/007).** 날짜 하나에 한 줄(이름·처음 값 여부). 코드에 날짜를 박지 않는다 — 임시공휴일·선거일이 해마다 생기기 때문이다.
- 고치는 곳: [요율] 화면 아래 '공휴일' 구역. [이전 해]·[다음 해], [공휴일 추가](날짜·이름 — 같은 날을 다시 넣으면 이름만 바뀐다), 줄의 [공휴일 삭제], [정해진 공휴일 넣기](날짜가 고정된 10일 가운데 그 해에 없는 날만: 1/1·3/1·5/1·5/5·6/6·7/17·8/15·10/3·10/9·12/25).
- 쓰이는 곳은 둘이다.
  1. **근무대장 개인 화면** — 날짜 옆에 공휴일 이름이 보이고, [평소대로 채우기]가 그 날을 '근무' 대신 **'유급 휴일'** 로 채운다(소정근로일일 때만 · 이미 적은 날은 건드리지 않는다).
  2. **연차 [사용 등록]** — 기간 안의 공휴일은 건너뛰고 '공휴일(이름)'으로 알려 준다(공휴일에 연차가 깎이지 않게).
- **5인 미만 사업장은 노동절(5월 1일)만** 유급 휴일로 본다(`isPaidHoliday`) — 관공서 공휴일의 유급 의무는 상시 5인 이상에만 있다. 사업장의 '상시 5인 이상' 값을 그대로 쓴다.
- 급여 계산은 바꾸지 않았다. 근무대장에 '유급 휴일' 줄이 저장돼야 급여에 들어가는 것은 전과 같다 — 목록에 날을 더하거나 지워도 **이미 저장한 근무대장은 바뀌지 않는다.**
- 처음 값: hr/007 이 2026년 22일 · 2027년 24일을 넣는다(대체공휴일·2026-06-03 지방선거일 포함). 2028년부터는 넣지 않았다(자료마다 설날 날짜가 달랐다) — [정해진 공휴일 넣기] 뒤 설·추석·부처님 오신 날·대체공휴일을 직접 더한다.

  · 저장은 지금처럼 근무대장의 `leave_days`(일)에 한다: 시간 ÷ 하루 소정근로시간, 소수 넷째 자리까지(8시간 근무자의 3시간 = 0.375, 7시간 근무자의 2시간 = 0.2857). 급여는 `leave_days × 하루 소정근로시간`을 유급 시간으로 치므로 그대로 맞는다.
  · **migration hr/009** — `work_logs.leave_days` 를 numeric(3,2) → numeric(5,4), 제약을 "0·0.25·0.5·1 가운데" → "0 이상 1 이하"로. 적용 전에도 하루 연차와 0.25·0.5 로 떨어지는 시간(8시간 근무자의 2·4시간)은 들어가고, 그 밖의 시간은 'DB 준비 전(hr/009)'으로 거절하며 아무것도 저장하지 않는다.
- **덮기.** 이미 기록이 있는 날을 바꾸게 되면 서버가 저장하지 않고 날짜마다 "전 → 후"를 돌려준다(`need_confirm`·`changes`). 창이 그 목록을 보여 주고 [덮어쓰고 등록]을 눌러야(`overwrite: true`) 저장한다.
  · 연차(하루): 그 날의 줄이 '연차'가 된다. 근무·결근·무급 휴무 등 다른 기록은 덮는다(비고는 남긴다). 이미 연차인 날은 묻지 않는다.
  · 시간: 그 날은 **'근무 + 연차 n시간'** 이 된다. 근무와 연차를 더해 하루 소정근로시간을 넘으면 **넘는 만큼 근무 시간을 줄인다.**
      - 평소대로 채워 둔 날(8시간) + 2시간 → 근무 6시간 + 연차 2시간(출퇴근 시각은 비운다 — 어느 쪽을 쉬었는지 모른다). 덮기 안내에 나온다.
      - 실제 일한 시간이 적힌 날(6시간) + 2시간 → 근무 6시간 그대로, 연차만 붙는다. 안내 없이 들어간다(바뀌는 근무 내용이 없다).
      - 기록이 없는 날 → '근무(평소 − n시간) + 연차 n시간'을 새로 넣는다. 연차만 넣어 두면 나중에 [평소대로 채우기]가 그 날을 건너뛰어 근무가 빠지기 때문이다.
      - 결근·무급 휴무·하루 연차가 들어 있던 날 → 덮기 안내 뒤 '근무(평소 − n) + 연차 n'.
  · 이 규칙은 대표에게 따로 묻지 않고 정했다(급여에 닿는다): "덮는다"를 시간 연차에 그대로 적용하면 근무 기록이 통째로 사라지므로, 하루 소정근로시간을 넘지 않게만 줄이는 쪽으로 했다. 다르게 원하면 바꾼다.
- 소정근로일이 아닌 날·공휴일·휴무일은 여전히 건너뛴다. 확정된 달은 DB 가 거절한다.
- 표시: 연차 화면·달력·근무대장에서 하루 = "연차", 그보다 적으면 "n시간"(`leaveText`). 근무대장 개인 화면의 '연차' 칸 고르기는 반차·반반차에 더해 시간으로 넣은 값이 있으면 그 값도 한 칸으로 보인다. 근무대장 엑셀은 시간 연차를 일수(0.375)로 내보내고 그대로 다시 읽는다.
- 사용 취소: 시간 연차는 연차 시간만 지운다. 줄여 둔 근무 시간은 그대로다(창이 그렇게 말한다).
- 확인: 가짜 DB 26건(덮기 안내와 그때 아무것도 저장되지 않는 것, 덮어쓴 결과, 시간의 세 경우, 0.375·0.2857, 급여 계산, 공휴일·확정된 달, 취소, 009 적용 전), 화면(가짜 응답).
- 확인하지 못한 것: SQL(hr/009)의 실제 실행, 실제 DB 에서의 저장.
