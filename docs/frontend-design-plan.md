# 업무도우미 디자인 개선 기획 — frontend-design 스킬 적용 (2026-10-17)

대표 요청: "frontend design 스킬을 설치했어. 이 스킬을 기반으로 업무도우미 개선 계획을 만들어줘."

스킬 원문: `~/.claude/plugins/marketplaces/claude-plugins-official/plugins/frontend-design/skills/frontend-design/SKILL.md`.
앞선 결정과의 관계: 2026-10-14 어포던스 1~3차 결정(`docs/ux-affordance-plan.md`, `docs/design-system.md` 맨 위 세 절)은 그대로 유효하다. 이 기획은 그 위에 "무엇을 더 의도적으로 만들 것인가"를 얹는다. 두 문서가 충돌하면 대표 결정이 먼저다.

## 0. 스킬이 말하는 것과 우리 상황

스킬의 핵심은 넷이다.
1. **주제에서 출발한다.** 무엇을 위한 화면인지, 누가 쓰는지, 주된 일이 무엇인지 먼저 적고 거기서 시각 선택을 끌어낸다.
2. **기본값이 아니라 선택.** 생성형 디자인이 반복하는 모양(크림 바탕+세리프, 카드 키트, 대문자 눈썹 라벨, 중점(·)으로 이은 메타 글자, 버튼 끝 화살표, 모든 섹션의 등장 애니메이션)은 "선택한 것"이 아니라 "손이 가는 것"이니, 브리프가 요구하지 않는 한 쓰지 않는다.
3. **과감함은 한 곳에.** 기억에 남는 요소 하나를 정하고 나머지는 조용히. 하나를 빼고 나가라(샤넬).
4. **글도 디자인이다.** 버튼은 벌어질 일을 그대로 말하고, 같은 동작은 흐름 내내 같은 이름을 쓴다(버튼 '발주 등록' → 토스트 '발주를 등록했습니다'). 오류·빈 화면은 분위기가 아니라 방향을 준다.

업무도우미는 외부에 보이는 랜딩 페이지가 아니라 **직원 10명 안팎이 매일 여는 내부 도구**다. 그래서 스킬의 항목을 그대로 쓰지 않고 아래처럼 가른다.

| 스킬 항목 | 우리 적용 | 근거 |
|---|---|---|
| 주제 기반 아이덴티티 | **적용** — 수산물 유통 운영 도구라는 사실에서 출발 | §1 브리프 |
| 생성형 기본값 피하기 | **적용(핵심)** — 우리 화면에 그 '티'가 실제로 있다(§2 측정) | 328곳의 '·', 버튼 화살표 11곳, 카드 445곳 |
| 히어로(첫 화면의 가장 특징적인 것) | **부분 적용** — 홈 첫 화면 한 곳만. 각 업무 화면엔 히어로를 두지 않는다 | 도구는 '들어와서 일하는 곳', 보여 주는 곳이 아니다 |
| 타이포가 성격을 만든다 | **적용** — Pretendard 한 가족, 숫자 표기 규칙을 '우리 것'으로 | 수치가 가장 많은 도구 |
| 과감한 색·서체·레이아웃 실험 | **적용 안 함** | 대표 결정: 유채색 3개, 장식 없음, 화려함 불필요 |
| 모션은 한 번의 연출만 | **적용** — 이미 모션이 거의 없다. 남길 하나를 정한다 | transition 30곳·keyframes 3곳 정리 |
| 글쓰기 규칙(동사 체인·오류·빈 화면) | **적용(핵심)** — 3차에서 버튼은 고쳤고 토스트·가이드와의 '같은 이름' 연결이 남았다 | §4-A |
| 계획 → 브리프 대조 → 구현 → 자기 비평 | **적용** — 화면별 비평 루프를 만든다(스크린샷은 베타 로그인 뒤 가능) | §5 |

## 1. 디자인 브리프 (스킬 1단계 — 주제·대상·주된 일)

- **주제**: 씨몬스터(수산물 가공식품 브랜드)의 운영 — B2B 발주, 온라인 발주·출고, 생산 요청·재고, 매출, 마케팅, CS. 재료의 세계는 어종·그램·상자·냉동·발송일이다. 화면에 가장 많이 나오는 것은 **품목명(광어순살(5kg x 2) · 200g)과 수량·금액·날짜**다.
- **대상**: 씨몬스터 직원 10명 안팎 + 대표. 매일 여러 번, 큰 모니터와 폰 둘 다. 대부분 숙련자이지만 새 직원도 가이드 없이 써야 한다(어포던스 1차 원칙).
- **주된 일**: 목록에서 오늘 처리할 행을 찾아 상태를 바꾸고, 숫자를 읽고, 가끔 긴 폼을 채운다. 읽기 7, 쓰기 3.
- **브랜드에서 가져올 것**: 주황 `#F15A30` 하나. 홈페이지 리뉴얼의 웜베이지·필 버튼은 소비자용이라 도구엔 들이지 않는다(대표 결정 2026-10-14 색 줄이기).
- **이 도구가 '누구의 것과도 헷갈리지 않을' 지점(스킬이 요구하는 한 가지)**: **숫자와 품목명의 표기법**. 수산물 도구답게 수량·그램·금액·날짜가 어디서나 같은 서체·같은 정렬·같은 단위 표기로 읽힌다. 색이나 장식이 아니라 '표기 규율'이 아이덴티티다.

## 2. 지금 상태 — 스킬의 '생성형 티' 체크리스트로 잰 결과 (2026-10-17 코드 측정)

| 스킬이 꼽은 티 | 우리 화면 | 판정 |
|---|---|---|
| 중점(·)으로 이은 메타 글자 'A · B · C' | 화면 코드 **328줄**(품목 '광어순살 · 200g ×1', 즐겨찾기 'B2B · 발주', 입금 '입금자명 · 금액' 등) | **있음 — 가장 큰 티**. 단 품목 표기의 '·'는 뜻(상품/규격 구분)이 있어 유지, 메타 문자열의 '·'만 정리 |
| 버튼·링크 끝 화살표 '→' | **11곳**('다음 단계 →', '← 이전', '송장 스캔 →', '화면 열기 →') | 있음 — 3차 라벨 규칙과도 어긋남 |
| 대문자 눈썹 라벨 | BETA 2, AI 1, NEW 1, 검색의 'Ctrl K' | 있음(소수). BETA·NEW는 상태 배지라 허용, AI는 한글 '초안'으로 |
| 모든 것에 같은 둥근 카드 + 같은 회색 그림자(카드 키트) | `.b2b-stat-card` 147 + `.b2b-card` 298 + 폼 섹션 19 = **464곳**. radius 8/12/16/50 네 가지, 그림자 두 가지 | 있음 — `.b2b-card`는 이미 투명 래퍼(테두리 없음)라 절반은 해소. 남은 것은 KPI 타일·홈 카드·폼 섹션이 같은 모양인 것 |
| 섹션마다 등장 애니메이션·카드마다 호버 트랜지션 | 등장 애니메이션 없음. 호버 transition 30곳(카드 translateY -2px, 색) | 거의 없음 — 카드 '떠오름'만 정리 |
| 크림 바탕+세리프+테라코타 | 흰 바탕+Pretendard+주황 | 없음 |
| 기본 숫자 타이포(큰 수 + 작은 라벨 + 그라데이션) | KPI 타일 47곳이 '라벨 12px + 값 24px' 한 가지 꼴 | 부분 — 그라데이션은 없으나 '큰 수 + 작은 라벨'이 기본값 그대로 |
| 글: 버튼 동사와 결과 문구 불일치 | 버튼은 3차에서 동사+목적어로 정리됐으나 토스트는 대부분 '저장했습니다'·'처리했습니다'로 **동작 이름을 되풀이하지 않는다** | 있음 — 동사 체인 끊김 |
| 줄 길이 80자 이내 | 리포트·가이드·공지 미리보기에 `max-width: 68ch` 규칙 있음(3-T) | 적용됨 |

잘 되어 있는 것(스킬 기준으로도 유지): 단일 서체, 유채색 3개, 장식 없음, 토큰 단일 소스, 상태=글자+색, 빈 상태에 다음 행동 버튼(3차 F1), 오류 문구 규칙(3차 E5), 초점 링·대상 크기.

## 3. 디자인 계획 (스킬 2단계 — 작은 토큰 체계로 적는다)

### 색 — 이름 붙인 5개 (이미 있는 토큰, 값 변경 없음)
| 이름 | 값 | 역할 |
|---|---|---|
| 씨몬스터 주황 | `#F15A30` | 1차 버튼 채움·현재 위치·로고. 글자로는 `#C8431C` |
| 먹색 | `#1A1A1A` | 모든 본문·제목·숫자 |
| 중간 회색 | `#555555` | 보조 글·머리글·라벨 |
| 종이 | `#FAFAFA` 바탕 / `#FFFFFF` 면 / `#F7F8FA` 머리글·호버 | 면 3단 |
| 경계 | `#E3E3E3` 기본 / `#C9C9C9` 입력칸 | 선 2단 |
| 이상·완료 | `#C92A2A` / `#22863A` | 값이 '나쁨/끝남'을 말할 때만 |

### 글자 — 한 가족, 역할은 굵기·수치 표기로
- Pretendard Variable 하나. 제목용 다른 서체를 두지 않는다(스킬: 한두 가족, 둘이면 뚜렷이 다르게 — 우리는 하나).
- 크기 5단 12/13/15/17/24, 굵기 400/600/700(2026-10-14 확정).
- **숫자 규율(아이덴티티)**: 모든 수치는 `tabular-nums`, 우측 정렬, 천 단위 쉼표, 단위는 값 뒤 한 칸 띄운 12px 회색('180,900 원'이 아니라 '180,900' + 열 이름이 단위를 말한다), 수량은 '×2'·'2개' 두 가지 중 하나로 통일(지금 둘 다 쓴다), 날짜는 'YYYY-MM-DD' 하나, 그램·kg는 품목명 안에만.
- 제목은 글자 자체가 구조다: 페이지 제목 24/700 하나, 섹션 제목 17/700, 그 아래 작은 눈썹 라벨·부제 설명문을 두지 않는다(카피 규칙과 같음).

### 레이아웃 개념 — 화면 세 틀
업무도우미의 73개 화면은 세 틀로 나뉜다. 틀마다 한 줄 원칙과 와이어프레임.

**① 목록 틀(발주·재고·VOC·거래처…)** — "제목 한 줄, 필터 한 줄, 표. 표가 곧 화면이다."
```
제목                              [2차] [2차] [1차 주황]
필터 ─ 검색 ─ 상태 ─ 업체 ─ … ─ 건수
───────────────────────────────────────────────
열이름(13/600 회색)  …  숫자열(우측)  상태  동작
행(13/400)          …  180,900       ▾    [복제][명세표]
```
왼쪽 정렬. 요약 타일(KPI)은 목록 위에 두되 '큰 수+작은 라벨' 기본꼴을 버리고 **한 줄 요약 띠**(§4-C)로.

**② 폼 틀(발주 등록·입출고 기록·요청서)** — "한 열, 위에서 아래로, 한 번에 한 질문."
```
제목
섹션 제목(17)
  라벨(12 회색)        라벨
  [입력칸 13]          [입력칸]
  오류 12 빨강
섹션 제목
  표(품목 줄)
─────────────────────────
                       [그만두기] [발주 등록]
```
폼은 최대 폭 720px, 라벨은 칸 위(왼쪽 라벨 금지 — 폰에서 깨진다). 1차 버튼은 맨 아래 오른쪽 하나.

**③ 읽기 틀(종합 리포트·가이드·공지 미리보기·통계)** — "글은 68자, 숫자는 표."
```
제목
요약 띠(핵심 수치 3~5개, 한 줄)
본문(68ch) ─ 표 ─ 본문
```

**홈(유일한 히어로 자리)** — "오늘 날짜와 이름으로 시작해, 전체 메뉴가 곧 첫 화면."
```
10월 17일 금요일, 현석        [검색 Ctrl K]
즐겨찾는 메뉴 ▸ (타일)
전체 메뉴 ▸ 분류 구역 + 카드(지금 모양)
```
스킬이 말하는 '가장 특징적인 것'을 홈에서는 **날짜·요일·이름 한 줄(24/700)**로 둔다. 큰 숫자·그라데이션·배너 없이, 도구가 '오늘'을 말하는 한 줄. (오늘 할 일 카드는 대표 결정으로 폐기 — 되살리지 않는다.)

### 원칙 5
1. 표기 규율이 아이덴티티다 — 숫자·단위·날짜·품목명 표기를 한 가지로.
2. 구조 장치는 정보일 때만 — 선·테두리·번호·배지는 뜻이 있을 때만 긋는다(단계가 아니면 ①②③ 금지, 구분이 아니면 '·' 금지).
3. 과감함은 홈의 한 줄에만 — 나머지 73화면은 조용하게.
4. 같은 동작은 흐름 내내 같은 이름 — 버튼·확인 창·토스트·가이드가 한 단어를 쓴다.
5. 움직임은 답할 때만 — 사용자가 한 일에 대한 응답(토스트 등장, 펼침)만 움직인다.

### 계획을 브리프에 대조한 결과(스킬 요구 — "다른 비슷한 브리프에도 똑같이 나올 계획인가?")
- 색·서체는 이미 대표 결정이라 그대로. 생성형 티 중 '크림+세리프+테라코타'와는 반대 방향이다.
- 홈 히어로를 '날짜·요일·이름 한 줄'로 한 것은 **아무 도구에나 들어갈 수 있는 기본값**이다. 수산물 운영 도구답게 고치면: 그 줄에 **오늘의 발송·입금 상황을 글 한 문장**으로("오늘 발송 2건, 입금 대기 3건 7,334,800원") 잇는 안이 있다. 대표가 오늘 할 일 카드를 뺐으므로 숫자 카드가 아닌 **문장 한 줄**로만 제안한다(§6 결정 1).
- KPI 타일을 '한 줄 요약 띠'로 바꾸는 것은 SaaS 카드 키트에서 벗어나는 선택이다. 다만 발주 관리의 상태 요약 카드는 **카드가 곧 필터 버튼**이라 뜻이 있다 — 거긴 남긴다.

## 4. 개선 항목

노력: S 반나절 · M 하루 · L 이틀.

### A. 글 — 동사 체인과 메타 문자열 (핵심)
| # | 바꾸는 것 | 왜 | 노력 |
|---|---|---|---|
| A1 | **동사 체인**: 버튼 → 확인 창 action → 토스트 → 가이드가 같은 동사. '발주 등록' 누르면 토스트 "발주를 등록했습니다", '기록 취소' 누르면 "기록을 취소했습니다". 토스트 문구를 전수(약 60곳)로 버튼 라벨에서 파생 | 스킬: 'Publish' 버튼은 'Published' 토스트를 만든다. 지금은 대부분 '저장했습니다' | M |
| A2 | **메타 문자열의 '·' 정리**: 즐겨찾기 'B2B · 발주' → '발주'(분류는 작은 글자 줄로), 검색 결과 '분류 › 툴 › 하위'는 유지(경로라 뜻이 있다), 입금 '입금자명 · 금액' 류 라벨은 둘로 분리. **품목 표기 '광어순살(5kg x 2) · 200g ×1'의 '·'는 상품/규격/수량의 구분이라 유지하되 규격을 회색으로 — 이미 그렇다** | 328곳 중 뜻 없는 것만. 전수 분류 뒤 약 1/3 예상 | M |
| A3 | 버튼·링크의 화살표 11곳 제거: '다음 단계 →'→'다음 단계', '← 이전'→'이전 단계', '송장 스캔 →'→'송장 스캔 열기', '소매 → 도매'(재고 이동 방향)는 글자 '소매에서 도매로' | 스킬 티 5번·3차 라벨 규칙 | S |
| A4 | 대문자 라벨: 'AI' 배지 → '초안'(AI가 만든 글), 'NEW' → '새 기능', BETA 는 유지(상태 배지), 검색 단축키 'Ctrl K' 유지(키 이름) | 스킬: 대문자 라벨은 생성형 티. 단 키 이름·상태 코드는 예외 | S |
| A5 | 오류·빈 상태 문구 재점검: "~할 수 없습니다"로 끝나는 문구에 **다음 행동** 한 토막 붙이기("…없습니다. 발송일을 먼저 등록하세요") — 3차 E5·F1 규칙에 '방향'을 더함 | 스킬: 오류는 무엇이 잘못됐고 어떻게 고치는지 | M |

### B. 구조 장치 — 뜻 있는 선만
| # | 바꾸는 것 | 왜 | 노력 |
|---|---|---|---|
| B1 | **카드 위계 3단 명문화**: ⓐ 투명 래퍼(`.b2b-card`, 선 없음 — 지금처럼) ⓑ 경계 카드(`.b2b-stat-card`, 1px 선, 그림자 없음) ⓒ 떠 있는 면(모달·토스트·검색 패널만 그림자). **표·폼·홈 카드의 그림자를 없애고 모달 계열에만 남긴다**. radius 는 2단(8 컨트롤 / 16 떠 있는 면)으로, 12·50은 버튼·배지 전용으로 남김 | 같은 둥근 카드+같은 그림자가 모든 것에 — 티 4번 | S(CSS) |
| B2 | 호버 '떠오름'(translateY −2px + 그림자 전환) 제거 — 호버는 바탕색 한 단계만 | 티 5번 | S |
| B3 | KPI 타일(47곳) → **요약 띠** 한 줄: '품목 수 50 · 재고 자산 34,371,924 · 부족 8건'을 가로 한 줄에 13px 라벨 + 15px/700 값으로. 발주 관리의 '카드=필터'는 유지 | '큰 수+작은 라벨' 기본꼴 탈피, 화면 위 공간 절약(대표가 글자·여백 축소를 두 번 요청) | M |
| B4 | 번호·구분선 점검: 발주처리 ①②③④ 는 진짜 단계라 유지. 그 밖의 번호 매김·불필요한 구분선 제거 | 스킬: 번호는 순서일 때만 | S |

### C. 표기 규율 — 수산물 도구의 아이덴티티
| # | 바꾸는 것 | 왜 | 노력 |
|---|---|---|---|
| C1 | **수량 표기 통일**: '×2' / '2개' / '2' 가 섞여 있다 → 표 안은 숫자만(열 이름이 단위), 문장 안은 'N개' | 같은 뜻 같은 모양 | M(전수) |
| C2 | 금액 단위: 표 안 '원' 글자 제거(열 이름 '합계(원)'), 문장 안은 '7,334,800원' | 숫자 열 정렬이 깨끗해진다 | S |
| C3 | 품목명 표기 한 함수(`formatItem`)로: 상품명 + 규격(회색) + 수량. 지금은 화면마다 조합이 조금씩 다르다 | 품목명이 이 도구의 '얼굴' | M |
| C4 | 날짜·기간 표기 한 함수: 'YYYY-MM-DD', 기간 '10-01 ~ 10-15', 상대 표기('D-3')는 발주 긴급도에만 | 혼용 제거 | S |

### D. 홈 한 곳의 히어로
| # | 바꾸는 것 | 왜 | 노력 |
|---|---|---|---|
| D1 | 홈 첫 줄을 '씨몬스터 업무 도우미' 제목 대신 **"10월 17일 금요일, 현석"** (24/700) + 그 아래 한 문장 "오늘 발송 2건, 입금 대기 3건" (13 회색, 대표 결정 1에 따라 선택) | 스킬: 첫 화면은 그 세계에서 가장 특징적인 것으로. 도구의 세계는 '오늘' | S |
| D2 | 즐겨찾기 타일은 그림자 없는 경계 카드로(B1), 전체 메뉴는 지금 구역+카드 유지 | 홈이 카드 키트처럼 보이지 않게 | S |

### E. 움직임 — 한 번

### F. 비평 루프 — 스킬의 4단계
| # | 만드는 것 | 왜 | 노력 |
|---|---|---|---|
| F1 | `docs/design-notes.md`: 화면별로 "시도한 것 / 뺀 것 / 대표 반응" 세 줄씩 쌓는 기록. 이번 10-14~16 의 결정(막대 제거, 레일 폐기, 글자 두 번 축소, 열 % 고정…)부터 적는다 | 스킬: 사람 창작자는 기억으로 새 시도를 한다 — 세션이 바뀌어도 같은 시도를 반복하지 않게 | S |

### G. 하지 않을 것
