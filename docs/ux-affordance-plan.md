# 업무도우미 UX 개선 기획 — 어포던스·사용성 (2026-10-14)

대표 요청: "최신 UX/UI 흐름을 배워 업무도우미에 적용할 점을 기획. 화려한 모션·애니메이션은 불필요. 사용자가 편하고, 기능이 어디 있는지, 무엇인지 바로 알 수 있어야 한다 — 어포던스와 사용성 최우선."

근거: (1) 2025~2026 내부 도구 UX 흐름 조사(NN/g·W3C WCAG 2.2·GOV.UK·Shopify Polaris·Atlassian·Shape of AI 등, §8), (2) 업무도우미 코드 전수 점검(2026-10-14, 메뉴 75개·화면 7종·공용 CSS·수치 집계).

## 1. 원칙 다섯 가지

1. **보이는 것이 곧 지도다.** 기능은 사이드바와 화면 위에 '보이게' 둔다. 검색·단축키는 보조일 뿐 숨긴 기능을 대신하지 않는다.
2. **눌리는 것은 눌리게, 눌리지 않는 것은 눌리지 않게 보인다.** 버튼·링크·선택칸·배지가 서로 다른 모양을 가진다. 커서나 툴팁에만 의존하지 않는다.
3. **한 화면에 1차 행동은 하나.** 주황 채움 버튼은 화면당 하나. 위험한 행동은 떨어뜨려 놓고 다른 모양으로.
4. **결과는 같은 자리, 같은 모양으로 알린다.** 성공·실패·진행 중의 표시 방식을 전 화면에서 통일한다. 브라우저 alert·confirm은 없앤다.
5. **유행은 거른다.** 반투명(글래스)·아이콘만 있는 메뉴·무한 스크롤·장식 모션·수치 신뢰도(92%) 표시는 쓰지 않는다. 다크모드는 유지할 인력이 생기기 전까지 하지 않는다.

### 색 줄이기 — 2026-10-14 대표 지시 "많은 색을 쓰지 말 것, 다양하면 정신없다"

위 규칙을 더 줄여 **유채색 3개 + 회색 단계**로 고정한다. 의미색 4종(danger·success·warning·info)은 2종으로 줄인다.

| 색 | 쓰는 곳 | 그 밖엔 금지 |
|---|---|---|
| **주황**(브랜드) | 1차 버튼 채움 · 현재 위치 막대·바탕 · 로고 | 링크·숫자·호버·아이콘·차트 |
| **빨강**(이상) | 오류 배너 · 삭제/취소 확인 버튼 · 진짜 이상치(품절·재고 마이너스·미수금 초과·실패) | 단순 '감소'·일반 강조 |
| **초록**(완료) | 완료·입금완료·발송완료·성공 배너 | 일반 '증가' 외 장식 |
| **회색 단계 4개**(검정 #1A1A1A · 중간 #555 · 흐림 #6B6B6B · 경계 #E3E3E3/#C9C9C9 · 바탕 #FAFAFA/#F7F8FA) | 본문·보조 글·테두리·바탕 · **대기·진행 중·일부·불필요·베타·AI·정보 같은 '중립 상태' 배지 전부**(회색 바탕 + 검정 글자) | — |

- **노랑(warning)·파랑(info)은 없앤다.** '발송대기·일부입금·부족·진행 중·확인필요'는 회색 배지에 글자로 구분한다. 색이 아니라 글자가 상태를 말한다. 단, '부족'처럼 행동이 필요한 상태는 배지 글자 앞에 작은 점이 아니라 **굵은 글자**로만 강조한다.
- 증감: 요약(KPI)에서 좋음=초록·나쁨=빨강은 유지하되 **±3% 안은 회색**(이미 결정). 표 안 숫자는 전부 검정.
- 링크: 검정 밑줄. 호버: 연회색. 선택된 행: 연주황 바탕(현재 위치와 같은 뜻 — '지금 다루는 것').
- 차트: 한 가지 색조의 명도 단계(주황 진함→연함 3단) + 회색. 범례는 글자로. 여러 계열이 꼭 필요하면 최대 4개까지 주황·회색·검정·흐린 회색. 지금 `PIE_COLORS` 팔레트는 이 규칙으로 교체.
- AI·베타 표시: 회색 배지 'AI'·'BETA' 글자만(보라 제거).
- 결과: 화면에 동시에 보이는 유채색은 **주황 하나 + (있을 때만) 빨강·초록**. 눈이 멈출 곳이 1차 버튼과 이상치뿐이 된다.

토큰 정리: `--sm-warning*`·`--sm-info*` 는 삭제하지 않고 **회색 세트를 가리키게**(값 재지정) 두면 lib 색 지도·배너 클래스를 안 고치고도 전 화면이 한 번에 바뀐다. 이후 2차에서 이름까지 정리.

### 적용 순서
1. 토큰 값 보정(`--sm-warning`·`--sm-orange-text`·`--sm-border`·`--sm-border-strong`) + 1차 버튼 글자 굵기 — `:root` 한 곳, 전 화면 자동(S, 1차).
2. 주황 글자 116곳을 역할별로 치환(링크→밑줄/info, 강조 숫자→검정 700, 활성→바탕+막대)(M, 1차~2차).
3. 토큰 밖 hex 65종·보라·Tailwind 회색 정리 + 디자인 문서 §3·§4 갱신(M, 2차).

## 6. 바로 보이는 효과 (사용자 입장)

- 탭 키로 움직여도 어디 있는지 보인다. 빨간 글자가 '버튼'으로 보인다. 발주 목록의 상태칸이 '바꿀 수 있는 칸'으로 보인다.
- 저장하면 늘 같은 자리에 같은 모양으로 "저장했습니다"가 뜨고, 실수하면 '되돌리기'로 돌린다. 브라우저 팝업이 사라진다.
- 메뉴 이름만 봐도 어느 변경 기록인지 안다. 종합 리포트가 '리포트' 묶음에 있다. 홈에서 오늘 할 일이 숫자로 보인다.

## 7. 측정

- 가이드 없이 처음 쓰는 직원 2명에게 과제 5개(발주 입금완료 처리, 어제 종합 리포트 보기, 재고 조정, 공지 만들기, 입금 확인필요 처리) — 소요 시간·막힌 횟수 전후 비교.
- 코드 수치: `:focus-visible` 0→전역, `alert(` 25→0, `confirm(` 96→파괴 행동만, 인라인 `fontSize` 500→0(공용 클래스), `is-responsive` 7→작은 표 전부.
