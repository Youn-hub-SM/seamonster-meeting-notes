# 매뉴얼 SharePoint 사이트 — 설계안 (2026-10-26)

대표 요청: GitBook 매뉴얼을 SharePoint 로 옮기되 **GitBook 같은 레이아웃**(왼쪽 목차 트리 · 가운데 본문 · 오른쪽 페이지 안 목차)으로, 씨몬스터 디자인 가이드라인에 맞게.
가이드라인 출처: `seamonster-manual/CLAUDE.md`(코랄 `#F15A30`, 검정 `#1A1A1A`, 흰 배경, 장식 없음, 크고 명확하게).

## 1. 사이트 종류 — 팀 사이트(그룹 없음)

GitBook 의 핵심은 **왼쪽 세로 목차**다. SharePoint 에서 세로(왼쪽) 탐색은 **팀 사이트**에만 있다. 커뮤니케이션 사이트는 위쪽 가로 메뉴뿐이라(2026-10 Microsoft 지원 문서: "왼쪽은 팀 사이트만") 맞지 않는다.

- 관리 센터 → 사이트 → 활성 사이트 → **+ 만들기 → 팀 사이트** → 아래쪽 **"Microsoft 365 그룹 없이 팀 사이트 만들기"** 선택(그룹을 붙이면 Outlook·Teams 에 그룹이 하나 더 생겨 지저분하다).
- 이름 `씨몬스터 매뉴얼`, 주소 `manual`, 언어 한국어, 소유자 대표.
- 권한: 사이트 방문자 = "조직의 모든 구성원", 구성원(편집) = 매뉴얼 담당 1~2명.

주의: 2026년 5월부터 새 SharePoint 디자인이 순차 적용 중이라 메뉴 위치·이름이 아래 설명과 조금 다를 수 있다. 바뀐 화면이면 그 화면 이름을 알려주면 다시 맞춘다.

## 2. 레이아웃 — GitBook 세 칸 구조를 SharePoint 로

| GitBook | SharePoint 구현 | 설정 위치 |
|---|---|---|
| 왼쪽 목차 트리(그룹 › 페이지) | 팀 사이트 왼쪽 탐색. 2단계까지(그룹 제목 → 페이지). 그룹 제목은 링크 없는 **레이블**로 | 왼쪽 탐색 맨 아래 [편집] |
| 가운데 본문 | 페이지의 2열 섹션(왼쪽 2/3) 에 **텍스트 웹 파트** | 페이지 편집 → 섹션 레이아웃 "3분의 2 왼쪽" |
| 오른쪽 페이지 안 목차 | 같은 섹션 오른쪽 1/3 에 **목차(Table of contents) 웹 파트**(제목 1·2 자동 수집) | 웹 파트 추가 → "목차" |
| 상단 검색 | 사이트 검색창(기본) — 페이지 본문까지 검색된다 | 없음 |
| 이전/다음 페이지 | 본문 맨 아래 "다음: ○○" 링크 한 줄(수동) | 텍스트 웹 파트 |
| 홈(스페이스 첫 화면) | 사이트 홈 = 그룹별 **빠른 연결** 카드 + "최근 바뀐 매뉴얼" 목록 | 홈 페이지 편집 |

빼는 것: 사이트 홈의 기본 "뉴스·활동·문서" 웹 파트는 모두 삭제(가이드라인 "두 번 말하지 않는다"). 페이지 머리글은 **최소(Minimal)** 레이아웃 — 큰 배너 이미지 없이 제목만.

## 3. 색·글꼴 — 가이드라인 적용

SharePoint 는 CSS 를 직접 못 넣는다. 테마(팔레트)와 머리글 설정으로만 맞춘다. `docs/sharepoint-theme.ps1` 이 테마를 등록한다.

| 가이드라인 | SharePoint 설정 |
|---|---|
| 코랄 `#F15A30` 은 "지금 할 수 있는 것"에만 | 테마 주색(themePrimary) = 코랄 → 링크·활성 메뉴·버튼에만 자동 적용 |
| 검정 `#1A1A1A` 텍스트, 흰 배경 | neutralPrimary = `#1A1A1A`, white = `#FFFFFF` |
| 회색 한 톤 `#6B6B6B` | neutralSecondary = `#6B6B6B` |
| 소프트 오렌지 배경 금지 | 머리글 배경 **흰색**(머리글 "배경" = 없음), 강조 배경 안 씀 |
| 장식 없음 | 머리글 레이아웃 **최소**, 사이트 로고는 검정 단색 로고(`seamonster(new)` 로고 파일), 푸터 끄기 |
| 크고 명확하게 | 본문은 "텍스트 웹 파트" 기본 크기 유지, 제목은 제목 1·2 만(제목 3 이하 금지), 표는 "테두리 있음" 스타일 하나로 통일 |

글꼴은 SharePoint 기본(Segoe UI → 한글은 맑은 고딕)에서 못 바꾼다. 브랜드 폰트 적용은 포기한다.

### 테마 등록

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\docs\sharepoint-theme.ps1          # SharePoint 관리자 로그인 창 → 테마 '씨몬스터' 등록
```

등록 뒤 사이트에서 톱니 → **모양 변경 → 테마 → 회사 테마 "씨몬스터"** 선택. 머리글은 **모양 변경 → 머리글** 에서 레이아웃 "최소", 배경 "없음(흰색)".

## 4. 페이지 템플릿 — 매뉴얼 한 장의 틀

사이트에 **페이지 템플릿** 하나를 저장해 두고 모든 매뉴얼 페이지를 거기서 만든다(새 페이지 → 템플릿 "매뉴얼").

```
[머리글: 최소 · 제목만]
[섹션: 3분의 2 왼쪽 | 3분의 1 오른쪽]
  왼쪽  텍스트 웹 파트
          한 줄 요약(이 매뉴얼이 답하는 질문 1문장)
          제목 1  ○○ 하는 법
          단계는 번호 목록, 버튼명은 [대괄호], 화면명은 「 」
          제목 1  주의
          제목 1  관련 매뉴얼 (링크)
          ― 다음: ○○ →
  오른쪽 목차 웹 파트 (제목 1·2)
         [선택] "이 페이지 담당: ○○ · 마지막 확인 YYYY-MM" 텍스트 한 줄
```

작성 규칙(업무도우미 가이드 문체와 같게): 부연 설명 금지, 한 단계 = 한 동작, 화면의 실제 버튼명 그대로, 이모지 없음, 색 강조 없음(강조는 굵게만).

## 5. 왼쪽 탐색 트리 — 초안

GitBook 구조를 그대로 옮기되 2단계로 눌러 담는다(SharePoint 왼쪽 탐색은 3단계부터 접혀서 불편). 실제 GitBook 페이지 목록을 받으면 이 표를 채운다.

```
홈
CS                      ← 레이블(링크 없음)
  응대 원칙
  주문·배송 문의
  교환·반품
  정기배송
세일즈
  쿠폰 등록 요청서
  채널별 프로모션
물류
  택배 발주(CNplus)
  송장 스캔
  입고·재고
관리자                   ← 민감 내용이면 별도 사이트로 분리(§7)
  업무도우미 설정
  연동 키 관리표(값 없음)
```

## 6. 홈 페이지 구성

1. 제목 "씨몬스터 매뉴얼" + 한 줄: "업무 순서는 여기서, 숫자는 업무도우미에서."
2. **빠른 연결** 웹 파트(레이아웃 "단추", 아이콘 없음) — 그룹 4개(CS·세일즈·물류·관리자)로 각 그룹 첫 페이지.
3. **강조 콘텐츠** 웹 파트 — 사이트 페이지 중 "수정일 최근 순" 5개, 제목 "최근 바뀐 매뉴얼".
4. 그 외 웹 파트 전부 삭제.

## 7. 권한·비서 연결

- 급여·인사처럼 민감한 내용은 이 사이트에 넣지 않는다. 필요하면 `manual-admin` 같은 **별도 사이트**를 만든다(비서는 사이트 단위로 읽으므로 페이지별로는 못 가린다).
- 비서가 읽게 하려면 `docs/ms365-grant-sites.ps1` 의 `$Sites` 에 `https://seamonster2016.sharepoint.com/sites/manual` 추가 → 실행, 업무도우미 설정 › 연결에 같은 주소 등록.
- **페이지는 지금 비서가 못 읽는다**(문서함 파일만). 페이지 읽기(Graph sitePages API)를 비서에 추가해야 한다 — GitBook 이전과 같이 진행(별도 작업, 반나절).

## 8. GitBook → SharePoint 이전 순서(다음 단계)

1. 사이트 생성·테마·템플릿(§1~4) — 대표 + 제가 안내
2. GitBook 내보내기(Git Sync 또는 API) → 마크다운
3. 변환 스크립트: 마크다운 → 페이지(텍스트 웹 파트 HTML) + 이미지 업로드 + 왼쪽 탐색 자동 구성
4. 검토 → GitBook 에 "이전됨" 안내 → 비서 페이지 읽기 추가

## 확인하지 못한 것

- 목차 웹 파트는 "순차 배포" 기능이라 테넌트에 아직 없을 수 있다. 페이지 편집 → 웹 파트 검색에 "목차"가 없으면 알려달라(대안: 본문 맨 위에 앵커 링크 목록을 텍스트로).
- 2026년 5월 새 디자인이 적용된 테넌트면 왼쪽 탐색 편집 위치가 다를 수 있다.
