# AI 비서 지식 통합 기획안 — 셰어포인트 단일 소스 + 비서 지침 칸 (2026-10-27)

대표 지시(2026-10-27): 회사 지식은 **셰어포인트 사이트**에 모두 올리고, 비서는 그 지식과 업무도우미 데이터만으로 말한다.
업무도우미 안에 따로 넣어 둔 프롬프트 지식(코드·DB·설정)은 셰어포인트로 옮기고 없앤다. 대신 업무도우미에 **비서 지침 칸** 하나를 둔다.
출발점은 비서가 낸 "매뉴얼 46페이지 vs 제 지식" 대조 보고서(2026-10-27).

## 1. 목표 상태

```
비서가 아는 것 = ① 셰어포인트 매뉴얼 페이지 + ② 셰어포인트 문서함 파일 + ③ 업무도우미 데이터(DB·광고·GA·재고 도구)
비서가 따르는 것 = ④ 비서 지침(관리자 화면의 칸 하나) + ⑤ 도구 설명(코드, 기술 설명만)
```

- 회사 **지식**(정책·기준·금액·담당자·절차·용어·해석 기준)은 ①에만 있다. 코드·DB·설정에 같은 내용을 두 번 적지 않는다.
- 비서 **동작 규칙**(어떻게 묻고, 어떤 도구를 언제 쓰고, 어떻게 표기하나)은 ④에만 있다. 관리자가 화면에서 고친다.
- ③·⑤는 데이터·기술이라 코드에 남는다(표 목록·스키마 주석·GA 카탈로그·도구 입력 형식).

## 3. 비서가 셰어포인트 지식을 쓰는 방식

46페이지 전부(수십만 자)를 매 턴 프롬프트에 넣을 수는 없다. 세 층으로 나눈다.

| 층 | 무엇 | 언제 넣나 | 크기 상한 |
|---|---|---|---|
| **목차** | 매뉴얼 전체 페이지의 제목·한 줄 요약·ref | 매 턴(10분 캐시) | 46페이지 ≈ 4,000자 |
| **핵심 지식** | 관리자가 지정한 페이지 본문 그대로(용어 정의·CS 보상 기준·담당자표·2026 OKR·톤 앤 매너·데이터 해석 기준) | 매 턴(10분 캐시, 프롬프트 캐시로 토큰 절감) | 합계 20,000자. 넘으면 뒤 페이지 잘라내고 경고 |
| **나머지** | 그 밖의 페이지·문서함 파일 | 질문 때 docs_search → docs_read 로 읽는다(색인) | — |

- 핵심 지식 지정 방법: **페이지 제목 앞에 `[비서]`** 를 붙인다(예: `[비서] 용어 정의`). 셰어포인트에서 바로 관리할 수 있고 업무도우미에 설정 화면이 따로 필요 없다. 화면에는 지금 탑재된 페이지와 글자 수만 보여 준다.
- 매뉴얼 페이지는 수정하면 10분 안에 비서에 반영. 문서함 파일은 색인 갱신(아침·오후·버튼) 뒤 반영.
- cs_coach·write_notice 도 같은 층을 쓴다: `[비서] CS 응대 기준`·`[비서] 톤 앤 매너` 페이지가 있으면 그 본문을 도구 지침으로 쓴다.

## 4. 비서 지침 칸(④)

- 위치: 관리자 › 설정 › AI 비서 › **비서 지침**. 큰 글상자 하나, [저장]·[기본값 되돌리기]·[미리보기(지금 프롬프트 전체)].
- 저장: `b2b_settings` kv `assistant_prompt`. 비어 있으면 코드의 기본값(지금 systemChat 에서 지식을 뺀 것).
- 기본값 구성: 역할 한 줄 → 분석가로 일하는 법 → 대화하는 법(되묻기 규칙) → 판단 규칙 → 표기 → SQL 규칙. 지식 블록은 전부 삭제.
- 프롬프트 조립 순서(코드): 지침 칸 → 도구 설명(코드) → 핵심 지식 페이지 → 매뉴얼 목차 → 데이터 설명(관계·루커·차단) → GA 카탈로그 → 문서함 목록.
- 지침 칸은 관리자만 고친다. 바꾼 사람·시각을 kv 에 같이 남긴다.

## 9. 지키는 규칙

- 셰어포인트에 없는 지식은 비서가 모른다. "비서가 틀렸다"는 "매뉴얼이 틀렸거나 없다"로 읽고 매뉴얼을 고친다.
- 코드에 회사 지식을 새로 적지 않는다(도구 입력 형식·데이터 설명만). 리뷰 때 "이 문장은 매뉴얼에 있어야 할 것 아닌가"를 묻는다.
- `[비서]` 페이지는 짧고 사실만. 설명·배경은 일반 페이지에 두고 링크한다.
